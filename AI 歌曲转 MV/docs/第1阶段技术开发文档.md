> 日期：2026-08-28

## 1. 阶段目标

第 1 阶段建立一条可持久、可恢复、可测试的真实后端链路：

邀请码登录  
→ 新建项目  
→ 上传 30—60 秒音频  
→ librosa 分析  
→ DeepSeek 生成 Plot/Storyboard  
→ 单 Cut 百炼 Wan 生成、失败重试、成功保留  
→ TimelineVersion  
→ FFmpeg Preview  
→ 16:9/9:16 独立 Export  
→ 下载 MP4

正式前端不属于本阶段。后端提供一页不追求视觉完成度的验收入口，用于上传、触发任务、查看状态和下载结果。

## 2. 完成定义

同时满足以下条件才算第 1 阶段完成：

1. 所有新接口由 FastAPI + Pydantic 提供；
2. Project、Job、Event、Cut、Artifact、TimelineVersion、Preview、Export 持久化到 SQLite；
3. 服务重启后能恢复非终态 Job；
4. SSE 断线后能按事件序号恢复，不重复日志；
5. 非法请求稳定返回结构化 4xx；
6. librosa 与 FFmpeg 既有回归测试通过；
7. Fake Provider 能覆盖成功、失败、限流、超时、部分成功和重试；
8. DeepSeek 真实 Storyboard 冒烟通过；
9. 默认 Wan VideoProvider 真实单 Cut 冒烟通过；
10. 当前 TimelineVersion 的 Preview 和两个 Export 版本一致；
11. 最小验收页能完成真实主链路；
12. README、版本和运行命令与实际实现一致；
13. `.env`、上传文件、生成文件和数据库不进入 Git；
14. 不包含正式前端、部署、付费或 P1 功能。

## 5. 数据库设计

### 5.1 数据库规则

- SQLite 开启 `journal_mode=WAL`；
- 开启 `foreign_keys=ON`；
- 设置 Busy Timeout；
- 时间统一存储 UTC ISO 8601；
- ID 使用带类型前缀的随机 ID；
- JSON 使用确定性序列化并保存内容哈希；
- Migration 在应用启动时单向执行；
- Repository 不返回裸数据库行，统一映射为领域模型。

### 5.2 核心表

| 表 | 核心字段 | 约束 |
|---|---|---|
| `users` | id、status、created_at | 用户 ID 唯一 |
| `invite_codes` | code_hash、status、expires_at、max_uses、used_count | 不存明文邀请码 |
| `sessions` | token_hash、user_id、expires_at | 不存明文 Token |
| `projects` | id、owner_id、name、current_timeline_version_id | 只允许 Owner 访问 |
| `audio_assets` | id、project_id、artifact_id、checksum、duration_ms、status | 同项目只有一个 active 音频 |
| `audio_analyses` | id、audio_asset_id、version、result_json、status、job_id | 分析版本不可覆盖 |
| `storyboards` | id、project_id、version、plot_json、status、job_id | Confirmed 版本不可原地修改 |
| `cuts` | id、storyboard_id、cut_version、order_index、start_ms、end_ms、spec_json、active_artifact_id、status | `(storyboard_id, order_index)` 唯一 |
| `artifacts` | id、project_id、type、storage_key、metadata_json、status、expires_at | storage_key 不接受用户路径 |
| `jobs` | id、type、status、resource_id、input_json、input_hash、idempotency_key、provider_request_id、lease、heartbeat、deadline、result_artifact_id、error | 幂等键唯一 |
| `job_events` | job_id、sequence、event_type、payload_json、created_at | `(job_id, sequence)` 唯一 |
| `timeline_versions` | id、project_id、version、content_hash、snapshot_json | `(project_id, version)` 唯一，快照不可变 |
| `previews` | id、project_id、timeline_version_id、completeness、status、job_id、artifact_id | Ready 必须有可用 Artifact |
| `exports` | id、project_id、timeline_version_id、aspect_ratio、resolution、status、job_id、artifact_id | 同版本同比例只允许一个 Current Export |

## 6. Job 与事件设计

### 6.1 Job 状态

```text
accepted → queued → running → succeeded
                       ├─ failed_retryable
                       ├─ failed_terminal
                       ├─ timed_out
                       ├─ cancelled
                       └─ unknown_provider_state
```

`unknown_provider_state` 只用于已提交远程任务但暂时无法确认状态的情况。Worker 必须查询原 `provider_request_id`，不能直接重新提交。

### 6.2 领取与租约

1. Worker 在事务内选择可运行的 `queued` Job；
2. 条件更新 Job 为 `running` 并设置 Worker ID、Lease 与 Heartbeat；
3. 更新成功才获得执行权；
4. 执行期间周期性刷新 Heartbeat；
5. 本地进程退出后，Recovery 扫描过期 Lease；
6. 本地 Job 重新入队，远程 Job 进入续查 Handler；
7. 超过 Deadline 后进入明确终态。

### 6.3 事件

每次状态或进度变化在同一事务中写入 Job 和 `job_events`。事件最少包含：

- `sequence`；
- `job_id`；
- `status`；
- `progress`；
- `message_code`；
- 安全的展示文案；
- `created_at`。

## 7. Provider 契约

### 7.1 StoryboardProvider

输入：

- 用户 Brief；
- BPM、目标时长；
- BeatPlan 摘要；
- Energy 段；
- 可选 Transcript；
- Cut 数量和时长约束；
- 输出 JSON Schema。

输出：

- Plot；
- 有序 Cut Spec；
- Provider Request ID；
- Model；
- Token Usage；
- 可安全记录的成本元数据。

后端随后执行：Schema 校验 → Cut 数量校验 → 连续覆盖校验 → Beat 边界归一化 → 保存 StoryboardVersion。

### 7.2 VideoProvider

契约分为：

- `create_task(input, idempotency_key)`；
- `get_task(provider_request_id)`；
- `download_result(result_url, artifact_target)`。

Provider 将厂商状态转换为统一状态，不把厂商原始错误直接返回用户。结果 URL 可能过期，因此成功后立即下载到 Artifact Store 并计算校验和。

P0 默认为 DashScope Wan `wanx2.1-t2v-turbo`。该模型每次固定生成 5 秒无声源片，只接受明确的 `size`；4—12 秒目标 Cut 在 RenderProvider 阶段裁切或循环对齐。Ark Seedance Provider 保留为可选兼容实现。

### 7.3 RenderProvider

- `build_preview(timeline_snapshot, completeness)`；
- `export(timeline_snapshot, aspect_ratio, resolution)`；
- `probe(artifact)`。

Preview 和 Export 只接受不可变 Timeline Snapshot，不直接读取“当前 Cut”，避免渲染过程中内容变化。

## 9. Timeline 与版本规则

TimelineVersion 内容哈希由以下字段生成：

- Audio Asset ID；
- Analysis Version；
- BeatPlan Version；
- Cut 顺序；
- Cut 起止时间；
- Active Video Artifact ID；
- Render Rules Version。

只有实际播放快照变化才创建新 TimelineVersion。Prompt 草稿变化但 Active 视频未改变时，不让当前 Preview/Export 失效。

Preview/Export Ready 必须同时满足：

1. 状态为 `ready`；
2. Artifact 存在且 ffprobe 通过；
3. 绑定的 TimelineVersion 等于项目当前版本。

否则只能显示为 `stale`、`missing_asset` 或失败，不能因为 URL 存在就显示当前已导出。

## 10. Preview 与 Export

### 10.1 Preview

- 后端 FFmpeg 构建；
- Full 与 Partial 明确区分；
- Partial 缺失 Cut 使用带序号的占位画面；
- 保留完整原音乐；
- 单 Cut Active Artifact 更新后创建新版本并重建。

### 10.2 Export

- Full Timeline 才允许正式导出；
- 16:9 与 9:16 是两个独立 Job；
- 两者绑定同一个 TimelineVersion；
- 9:16 使用确定性中心裁切/缩放与安全区规则；
- 输出 MP4、H.264、AAC；
- 成功后使用 ffprobe 验证编码、分辨率、时长和可读取性。

## 11. 统一错误

错误响应格式：

```json
{
  "error": {
    "code": "audio_duration_out_of_range",
    "message": "音频时长必须在 30—60 秒之间。",
    "retryable": false,
    "details": {
      "min_seconds": 30,
      "max_seconds": 60
    },
    "request_id": "req_example"
  }
}
```

分类：

- 输入错误：400/413/415/422；
- 未登录或无权限：401/403；
- 资源不存在：404；
- 幂等冲突：409；
- Provider 限流或暂时不可用：503，并标记 Retryable；
- 未知异常：500，返回安全文案并记录 Request ID。

## 15. 风险与控制

| 风险 | 控制 |
|---|---|
| SQLite 同时写入冲突 | WAL、短事务、Busy Timeout、单机 Worker 并发上限 |
| Worker 进程退出 | Lease、Heartbeat、Recovery |
| 视频模型重复计费 | 幂等键、先保存 Provider Request ID、重启只查询 |
| 模型输出不合法 | Schema + 业务归一化；不保存半合法 Storyboard |
| 临时 URL 过期 | 成功后立即下载到 Artifact Store |
| 本地磁盘增长 | 临时文件 24 小时、非 Active 资产 7 天、项目 30 天规则 |
| Key 泄漏 | `.env` Ignore、日志脱敏、提交前扫描 |
| Mac/Linux 不一致 | Python 3.11、`os.devnull`、CI 媒体 Fixture、禁止写死本机路径 |
| 正式前端提前侵入 | 验收页独立且明确不复用为正式前端 |
