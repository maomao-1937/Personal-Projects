# AI 歌曲转 MV：技术适配声明

> 阶段：第 1 阶段后端能力建设  
> 日期：2026-08-28  
> 状态：已完成阶段 1 实现、Wan 离线契约与一次授权的真模型冒烟  
> 依据：《AI 歌曲转 MV PRD V1.1》、三份通用技术栈手册、当前 `auto-beat-video-engine` 仓库

## 1. 适配结论

当前仓库不是空白项目，已具备真实的音乐分析与视频渲染能力。第 1 阶段不重写现有算法，而是在其外层补齐产品化所需的持久任务、Provider、版本、恢复、验证和最小验收入口。

采用以下架构：

- Python 3.11；
- FastAPI + Pydantic；
- SQLite WAL + 标准库 `sqlite3`；
- 同进程异步 Worker；
- pytest；
- `httpx` 调用 OpenAI Compatible、阿里云百炼 DashScope 与可选火山方舟 API；
- librosa 负责音乐分析；
- FFmpeg/ffprobe 负责 Preview、Export 和媒体验收；
- 后端提供纯 HTML/JavaScript 最小验收页，不开发正式前端。

本阶段不引入 PostgreSQL、Redis、Celery、云对象存储或正式 Next.js 应用。该选择满足单机可恢复验收，并保留后续替换 Repository、Worker 与 Artifact Storage 的边界。

## 2. 当前仓库事实

### 2.1 已验证、必须保留

- `pipeline/audio_analyzer.py` 已使用 librosa 输出 BPM、Beat、Downbeat、Onset、RMS Energy 和时长。
- `pipeline/beat_sync.py` 已按 Energy、Onset 和 Downbeat 评分，并将切点吸附到帧网格。
- `pipeline/exporter.py` 已使用单次 FFmpeg `filter_complex` 输出 H.264/AAC MP4。
- FastAPI 已有真实任务启动、SSE 进度和下载接口。
- 本机 FFmpeg/ffprobe 版本为 8.1.2，包含 H.264 编码能力。
- 本机已安装 Python 3.11 与 `uv`，可建立隔离环境。

### 2.2 需要替换或补齐

| 当前实现 | 风险 | 第 1 阶段处理 |
|---|---|---|
| Job 保存在进程级字典 | 重启丢失，不能恢复 | SQLite 持久化 Job、租约、事件和结果 |
| 单个 `asyncio.Queue` 承载 SSE | 多客户端争抢、断线丢事件、日志重复 | 持久事件序列 + `Last-Event-ID`/`after` 恢复 |
| 前端 SSE `onerror` 后直接关闭 | 页面永久停在 Processing | 最小验收页读取 Job 快照并自动重连 |
| 表单构造 Pydantic 对象时未统一处理异常 | 非法参数可能返回 500 | 统一 4xx 错误模型和异常处理器 |
| yt-dlp Node 路径和 `NUL` 写死 Windows | Mac/Linux 不完整 | P0 主链路不使用 YouTube；跨平台路径改由配置/`os.devnull` |
| 测试是手工网络脚本 | 无 pytest、无法 CI | 建立单元、接口、恢复、版本与 Provider 契约测试 |
| README/API/页面版本不一致 | 交付状态不可判断 | 单一版本来源，文档与 API 读取同一版本 |
| 文件仅有本地路径 | 缺 Artifact 元数据与归属 | 本地 Artifact Store + SQLite 元数据；接口不暴露任意路径 |

## 3. 与通用技术栈手册的适配

### 3.1 直接采用

- FastAPI、Pydantic、pytest；
- 后端任务状态作为唯一事实来源；
- SSE 只负责增量通知；
- 模型输出经过 Schema 和业务规则双重验证；
- Provider、Base URL、Model、Timeout、Retry 由环境变量配置；
- Mock/Fake 测试与真实模型冒烟分离；
- 密钥不进入代码、前端、README、日志或 API 响应。

### 3.2 根据当前范围收敛

- 持久化采用 SQLite，而不是在 P0 引入 PostgreSQL；
- Worker 与 API 同进程运行，但通过 Repository 和 Job Handler 解耦；
- Artifact 在开发期保存在本地受控目录，上线前再替换 TOS；
- 不使用专业消息队列，但实现租约、心跳、幂等和重启恢复；
- 不实现正式前端，只提供后端自带的最小验收页。

### 3.3 延后到后续阶段

- Next.js、TypeScript strict、Tailwind CSS；
- veFaaS、TOS、CDN 与域名；
- Redis、独立 Worker、多实例并发；
- 付费、积分、会员和多人协作；
- 专业 Timeline、复杂转场、Lipsync 与多候选图片。

## 4. Provider 适配

| Provider | 第 1 阶段实现 | 业务约束 |
|---|---|---|
| AudioAnalysisProvider | Librosa Provider | 保留现有真实分析；结果序列化为稳定 JSON |
| StoryboardProvider | OpenAI Compatible Provider | 从环境变量读取配置；严格输出 Plot/Storyboard JSON |
| VideoProvider | DashScope Wan Provider（默认）；Ark Provider（兼容） | 创建异步任务、保存 `provider_request_id`、恢复时只续查原任务 |
| TranscriptionProvider | Disabled Provider | 不阻塞主链路；页面显示未启用歌词分析 |
| RenderProvider | FFmpeg Provider | 生成 Preview 与两个比例 Export，并用 ffprobe 验证 |

业务服务只依赖 Provider Protocol。厂商字段映射、鉴权、错误转换和轮询封装在 Provider 内部。

## 5. 持久任务适配

### 5.1 SQLite

- 每次 Repository 操作使用独立连接；
- 启用 WAL、外键和 Busy Timeout；
- Schema 通过显式版本迁移初始化；
- JSON 输入快照保存前生成哈希；
- Job Event 以 `(job_id, sequence)` 唯一约束去重。

### 5.2 Worker

- Worker 事务性领取 `queued` Job；
- 领取后写入租约、Worker ID、开始时间和 Heartbeat；
- 任务到达终态时同时写入结果和事件；
- 重启后，租约过期的本地任务重新排队；
- 已有远程请求 ID 的视频任务恢复查询，不重新创建收费任务；
- 同一幂等键只允许一个有效 Job。

### 5.3 SSE

- Job 快照由普通 GET 返回；
- SSE 从持久事件表读取增量；
- 支持 `Last-Event-ID` 和 `after`；
- 无事件时发送 Keepalive；
- SSE 中断不修改 Job 状态；
- 客户端按 sequence 去重。

## 6. 安全与配置

- 真实值只保存在仓库根目录已忽略的 `.env`；
- 仓库提交 `.env.example`，只包含变量名和安全占位符；
- Provider Key 只在后端进程内读取；
- 日志仅记录 Provider、Model、Request ID、耗时、状态和估算成本；
- 错误响应不得包含鉴权头、Key、本地敏感绝对路径或 Provider 原始响应全文；
- 邀请码和 Session Token 使用哈希保存；
- Artifact 下载必须验证项目归属；
- 已发现的未忽略 `.env.save` 已删除，并加入 `.gitignore`。

## 7. 真实模型验证边界

- DeepSeek：一次最小 Plot/Storyboard JSON 冒烟；
- Wan：一个 `wanx2.1-t2v-turbo`、5 秒、480P、无声的单 Cut 任务；
- 真实冒烟使用专门 pytest Marker，默认测试不会调用外部模型；
- Wan 调用前报告 Model、固定时长、分辨率、预计调用次数和估算费用，不输出 Key；
- 上游接受任务后，只按任务 ID 查询，禁止因本地超时重复创建；
- 冒烟输出作为受控 Artifact 保存，不进入 Git。

## 8. 不兼容或需要特别处理的事项

- 系统自带 Python 3.9.6 不满足当前类型语法和阶段目标，必须使用已安装的 Python 3.11。
- 当前解释器未安装 FastAPI、librosa、pytest 等依赖，需在设计审阅通过后创建 `.venv` 并安装锁定依赖。
- 当前 `.env` 的变量已配置，但现有代码尚未加载这些新 Provider 配置；只有阶段 1 实现完成后才生效。
- `wanx2.1-t2v-turbo` 固定生成 5 秒源片；P0 目标 Cut 的 4—12 秒由 FFmpeg 裁切或循环对齐，不向模型传非法时长。
- 中国内地百炼 Base URL 可能是通用 DashScope 域名或控制台给出的 Workspace 专属域名，以当前账户控制台为准。
- 开发期 SQLite 和同进程 Worker 只承诺单机可恢复；多实例部署前必须升级领取锁、数据库和文件存储方案。

## 9. 技术适配结论

阶段 1 可以在不重写已验证算法的情况下完成。推荐方案以最少基础设施补齐真实产品链路，并把未来迁移到 PostgreSQL、独立 Worker 和 TOS 的变化限制在 Repository、Job Runner 与 Artifact Store 边界内。
