# V4 产品定位与 Agent 工作流建议

日期：2026-09-13；2026-09-14 更新。状态：用户已批准 Lovart 核心图片工作台复现，本地 V4 已实现。以下“当前问题”表为改造前基线，建议段保留决策历史，以文末实施状态为准。本轮先完成 Agency Agents 参考及运行时 Skill 加载与追溯，详见 AGENT-ARCHITECTURE.md。本文不将未来能力当作当前 PRD、DESIGN 或密钥管理实现。依据：用户要求一次接入后专心创作，保留 Agent 创作与自己控制，减少补充续跑和反复确认；项目用于面试展示及持续模型实验。

## 产品定位

建议定位为「上传人像，一次完成犬系分身的 AI 创作工具」，以自然衔接、犬种表现和原图保留作为具体任务。跨模型实验为作者的研究能力及作品验证服务，作为进阶入口，不要求每个创作者先学习模型体系。

区分两个使用角色：创作者上传、表达要求、看作品；维护者接入模型、设默认值、管理调用额度并开展实验。考虑到面试展示用途，推荐维护者统一接入，访客直接体验。访客自带 API 不作为默认使用门槛。

## 竞品事实与可借鉴点

研究范围为官方公开说明与教程，未登录实测竞品，也未验证其内部模型路由或效果声明。

1. Lovart 官方说明：用户提供需求与参考，Agent 选择工具并生成、编辑资产；常见任务可由 Skills 编排多步。可借鉴的是任务内自动执行与输出后编辑，不照搬无限画布。来源：[How Lovart Works](https://www.lovart.ai/docs/getting-started/how-lovart-works)。
2. Lovart 支持 Auto 模型偏好、手动偏好、使用 @ 锁定模型；Image Generator 可指定模型并绕过 Agent 直接生成。可借鉴的是「同一模型资源，两种控制方式」，不是接入两套互不相干的系统。来源：[Selecting AI Models](https://www.lovart.ai/docs/how-to-prompt/selecting-ai-models)。
3. Krea 模型目录同时列出 Auto 与具体图像模型；官方将 Auto 描述为按提示和套餐自动选模型。这只证明自动选择入口存在，不证明自动选择始终最优。本项目先记住默认绘图模型，不宣称自动找到最佳模型。来源：[Model Library](https://www.krea.ai/models)。
4. Adobe 官方教程通过相同提示词切换模型，并演示同一提示与构图参考在 Boards 中比较输出。可借鉴的是保留任务输入再换模型，避免让用户重新填写任务。来源：[See how different AI models transform the same prompt](https://www.adobe.com/learn/firefly/web/partner-ai-models)。

Lovart 的公开流程也允许在信息缺失时询问；不能把竞品概括为绝不提问。本项目需要比通用设计 Agent 更窄、更确定的工作流。

## 模块关系

| 模块 | 职责 | 在产品中的位置 |
| --- | --- | --- |
| 模型资源 | 保存供应商连接及模型能力，指定默认绘图与助手配置 | 低频管理设置 |
| Agent 创作 | 理解意图、采用犬种规则、组织方案、绘图、具备视觉能力时检查 | 默认创作方式 |
| 自己控制 | 用户设置犬种、表情、质感，直接绘图；不经过独立理解调度 | 同页第二种创作方式，可标注「直接生成」 |
| 模型对比 | 固定某次任务的输入，交给多个绘图模型分别执行 | 结果旁「换模型对比」及进阶实验入口 |

理解模型与绘图模型是能力角色，不必是两个厂商。一个供应商凭证可以关联其实际支持的多个模型，但配置不能默认把文字模型当作图像编辑模型。同一连接下的模型 ID、协议及能力仍须核对。

## 一次接入的含义

建议维护者在管理端完成供应商连接、凭证、模型能力及默认配置后保存。前台仅获取可用模型名称、能力和状态；不回传凭证。会话刷新继续使用服务端配置，只有密钥失效、额度不足或主动切换供应商才需要维护。

当前会话内存方案不具备这个能力。实现需要受保护的管理入口与服务端凭证保存；部署初期可由服务端密钥配置承载，带编辑界面的后台再加入加密凭证管理。不能用前端 localStorage 保存原始 API Key 来实现「记住」。公开体验还需维护者设置调用额度，并在生成前呈现本次使用范围；暂不扩展成收费或用户账号系统。

## Agent 的主路径

上传单人人像 → 可选一句要求/犬种 → 点击开始创作 → 检查输入与约束 → 理解照片和要求 → 自动完成造型方案 → 调用默认绘图模型 → 有视觉能力时检查结果 → 交付作品。

- 用户未指定的嘴型、舌头、神态、犬种等，按已选内容和任务默认值决定。方案作为可查看的执行摘要，不作为必须批准的步骤。
- 首页默认不出现「带着补充继续创作」及等待通用批准的状态。不会询问「是否继续」「可以开始了吗」「还要补充什么」。
- 多人目标不明确、图片不可用、明确约束冲突等真正阻塞项，使用一次具体的就地输入校验；尽量在绘图前解决。不能通过猜测目标或扩大修改范围来避免所有提问。
- 状态只显示正在理解、生成、检查等真实步骤，方案与调用详情收起。检查失败仍交付图像并说明未完成检查。
- 自动修正仅在用户预先允许的上限内、且有效视觉检查指出问题时执行；次数耗尽就交付并说明，不转成无限续跑。
- 未配置视觉助手时不能伪造看图和检查。维护者可选择文字策划版本，其实际可用步骤和前台描述同步。
- 结果下保留可选「修改这张」入口，输入如「嘴巴闭上，其他保持不变」后直接执行修改任务。结果修改不是首轮完成的必经步骤；仍需明确发送，不能在输入、失焦时自动付费绘图。

Agent 的价值在于根据输入与观察选择工具、处理约束并决定是否修正；多轮聊天本身不是目标。现有两份运行时 skill 可以继续承载造型和检查规则，不需要通过堆叠通用 skill 增加交互步骤。

## 自己控制与对比

自己控制：上传 → 选择犬种、表情与质感 → 使用已保存的默认绘图模型 → 生成。高级区域允许主动切换模型，切换创作方式不会要求重新接入。

对比应从某次作品或已冻结的创作任务进入，继承原始照片、实际完整绘图提示词、方案与修改范围，选择另外的绘图模型后执行。理解模型不应分别为每个模型改写提示词，否则混合了策划与绘图两个变量。记录真实耗时、失败和输出，不由一次试验自动生成能力排名。参数无法统一时如实注明。

## 推荐的信息架构与改造顺序

首页突出「Agent 创作 / 自己控制」，沿用照片与操作并置的现有视觉。模型默认值收在高级选项，管理放入设置；结果旁放「下载」「修改这张」「换模型对比」。模型实验保留独立地址用于作者研究与展示，但不占据首次创作的主操作。

1. 统一模型资源与默认值，打通跨刷新可用的服务端接入。
2. 将 Agent 主路径改为一次输入自动交付，移除通用审批及问答续跑依赖；保留具体阻塞输入校验。
3. 对比从真实任务快照建立基线，复用原图与实际绘图提示词。
4. 再调整导航、模式解释、结果动作和移动端布局，并完成浏览器验证。

验收目标（尚未测量）：配置正常的单人人像主路径一次提交完成，无方案批准；切换创作方式、刷新不要求重填有效连接；默认值由维护者控制；对比使用同一任务快照；异常不清空已有结果；后台绘图次数上限可验证。真实模型效果、访客实际成功率和公开部署仍需后续验证。
