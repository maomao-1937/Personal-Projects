# 狗头人工坊 · Agent 升级方案

状态：2026-09-12 用户已确认独立设计方向，V2 已进入本地实现。以下保留前期方案推导；当前已实现范围以 README、PRD 和实际代码为准。真实供应商实测与上线未完成。

实现差异：四项能力合并为两份运行时 skill 和六个工具。方案展示结构化字段，通过自然语言补充更新，尚无逐字段编辑器。跨会话记忆、正式评测库与评分未实现。手机先展示效果缩略图和输入，完整画布在后，主操作固定底部。

## 当前版本的具体缺口

1. 首页主要由三项固定犬种、模型下拉框和大幅静态示例组成；视觉重心是预制作品，用户自己的创作意图没有足够位置。
2. 表单垂直占据较多空间，犬种无图像依据，用户很难想象不同狗头的实际外观。
3. 主任务是创作，但用户先面对接口选择；模型实验的重要性不应转化为初次创作的操作负担。
4. 仅有柴犬、哈士奇、金毛，无搜索、别名或自定义目标。
5. `buildPrompt` 只有固定模板拼接，缺少犬种外观、编辑范围、配饰处理和冲突消解。例如默认保持头部朝向，补充示例却建议歪头。
6. 当前程序调用一次图像 API 就结束。没有理解意图的模型、工具决策、原图与结果的视觉检查、基于反馈的版本迭代，不能表述为已实现 Agent。
7. 目前的“停止 / 重试”属于请求恢复，不是模型观察结果后决定如何修正。

## Skill 的两层用途

开发侧：已发现并读取 Impeccable、frontend-design、UI/UX Pro Max。Impeccable 用于重新设计和审查；frontend-design 用于建立产品特有的视觉结构；UI/UX Pro Max 用于辅助校准基础可用性。不需要为了数量再安装一批相似 UI skill。

`Agent Development` 现有技能面向 Claude Code 插件子代理文件，不能直接作为本网站的 Agent 后端。安装本地 skill 也不会自动给网站增加工具调用能力。

产品侧：建议把以下四个能力写成项目内可版本管理的 skill 包，并让运行时实际读取提示、校验结构化输出和执行对应工具。只有文档、没有加载与执行代码时，只能称为设计资产。

| 能力 | 输入 | 输出与职责 |
| --- | --- | --- |
| 人像与意图理解 | 原图、用户要求、可选犬种 | 可观察的姿势、遮挡、光照、配饰；编辑目标与需要澄清的冲突 |
| 狗头造型设计 | 已理解的意图、犬种目录 | 犬种、外观特征、表情、允许改变的范围、必须保留的内容 |
| 图像编辑 | 经校验的造型方案、原图、所选模型 | 调用现有图生图 adapter，记录真实工具输入与结果 |
| 结果检查与修正 | 原图、生成图、方案 | 有证据的差异描述、无法判断项、是否需要修正及具体修正指令 |

不从脸推断真实人格或身份。“酷一点”“憨一点”是用户指定的造型意图，可以用于推荐；不能声称从人像算出了用户适合的犬种。

## 推荐的产品体验

上传照片后，用户说：“帮我变成一只很有精神的边牧，保留眼镜和西装。”

Agent 输出简短可编辑方案：“边境牧羊犬；保留眼镜、西装、姿势和背景；只替换头部，精神一点。”关键字段旁可直接调整，不让用户编辑大段系统提示。

完成生成后，Agent 对照原图检查犬头衔接、身体、衣服、背景和用户指定细节。如果眼镜缺失，显示具体观察并给出“补回眼镜”的修正动作。后续用户可以继续说“耳朵再自然一点”。必须保留每次输出和修正来源，不能覆盖旧结果后冒充一次成功。

### UI 结构候选

| 方案 | 主体 | 优点 | 风险 |
| --- | --- | --- | --- |
| A · 画布 + 造型助手（推荐） | 大幅用户图像画布，紧邻简短对话和方案；底部版本缩略图 | 同时体现图像创作与 Agent 的判断，保留高效修改路径 | 助手栏须克制，不能堆满聊天气泡 |
| B · 对话优先 | 中央对话流，图像作为消息中的大幅结果 | 自然语言输入门槛低 | 比较原图和多版本时容易上下翻找 |
| C · 犬种探索优先 | 犬种视觉目录先选造型，再进入编辑工作台 | 趣味和可发现性更强 | 首次生成路径更长，Agent 存在感较弱 |

推荐 A：桌面画布约占 2/3，助手约占 1/3；顶栏只保留创作、模型实验、接入设置。原图/结果同一画布切换，版本选择紧邻画布。没有上传时以明确标注的交互示例解释效果，不再让一张静态狗头人摄影图占据全部视觉表达。

手机：画布摘要 → 一句话输入 → 推荐方案 → 主操作；完整版本对比按需展开。操作与当前图片保持接近，不把三栏桌面压成很长的表单。

UI 状态必须覆盖：未上传、图片准备中、未接入理解模型、理解中、需要澄清、方案可编辑、生成中、检查中、结果可用、检查不可用、需要修正、达到次数上限、网络错误、停止。只展示真实工具进展和简短决策摘要，不伪造思考过程。

## 犬种与提示词升级

第一批建议 24 个目录项：柴犬、哈士奇、金毛、萨摩耶、边境牧羊犬、德国牧羊犬、拉布拉多、柯基、比熊、博美、贵宾犬、雪纳瑞、巴哥、法国斗牛犬、比格、杜宾、罗威纳、达尔马提亚、伯恩山、秋田、阿拉斯加、吉娃娃、西高地、马尔济斯。

- 常用犬种显示视觉缩略图；其余通过搜索/分类访问，不能在首屏铺 24 个按钮。
- 支持“边牧 / 边境牧羊犬”“泰迪 / 贵宾犬”等检索别名；提示词采用规范犬种和用户指定造型。
- 自定义犬种作为明确文本输入，不擅自转换成已知目录项；Agent 无把握时说明，允许用户补充参考图或外观描述。
- 每个目录项维护：中文名、英文名、别名、可观察形态描述、缩略图来源。目录条数不等于生成质量覆盖，需逐步积累实测。

### 结构化造型方案

```json
{
  "target": "主要人物的头部",
  "breed": "边境牧羊犬",
  "appearance": ["黑白毛色", "自然犬类口鼻"],
  "expression": "精神、专注",
  "preserve": ["西装", "眼镜", "人类身体和手", "原姿势", "背景与光照"],
  "allowChanges": ["人物头部及必要的颈部衔接"],
  "clarification": null
}
```

最终提示词由方案编译，明确四层内容：任务 → 犬种与造型 → 保留/允许改变范围 → 有针对性的质量约束。用户修改表情或头部角度时，更新相应约束，不能在末尾追加一条互相矛盾的要求。

边牧示例：

> 编辑上传的人像照片，仅把主要人物头部替换为真实的边境牧羊犬头部，呈现自然黑白毛色与犬类口鼻，神态精神、专注。保持原来的头部朝向，犬头比例适合人物肩宽，颈部自然衔接。保留原图的眼镜，使镜架随新的口鼻结构自然贴合；保持西装、人类身体与手部、姿势、构图和背景不变。匹配原图光照方向、阴影与清晰度。画面仍是一位穿着西装的人类身体配犬头；避免额外耳朵、残留人脸、毛发遮住镜片和明显拼贴边缘。

这是一条可供实测的改进提示，不是已验证优于旧提示的结论。应使用同一组照片做新旧提示对照，记录犬种识别、人体保留、衔接和细节遵循情况。

## 运行时架构

保留 React、Express、现有四类图生图 adapter 和出站网络边界。增加支持图像理解与工具调用的通用模型入口，负责理解、选择下一步和检查；绘图模型继续负责生成。两种模型职责必须分开，不能假定图像编辑端点能读图评判或调用工具。

建议工具：`inspect_portrait`、`lookup_breeds`、`propose_edit`、`generate_image`、`inspect_result`、`revise_edit`、`finish`。这些是待实现的产品运行时工具，不是当前 Codex 工具。

Agent 根据观察选择澄清、查犬种、生成、检查、修正或结束。服务端负责参数验证、密钥隔离、工具白名单和次数上限。若运行路径完全写死，只能称为 Agent 工作流；不能用名称替代动态决策能力。

### 调用和状态边界

- 方案阶段只调用理解模型；实际绘图次数与是否允许一次自动修正，在开始前明确展示，由用户在产品中设置。
- 建议首版最多 2 次图像生成（首张 + 一次修正），达到上限后返回已有作品与未解决问题，不无限重跑。
- 密钥只驻留会话；Agent 不读取密钥正文，不决定任意域名或任意模型，执行器只接受用户已接入且授权的配置 ID。
- 原图在首次理解阶段就会发送给理解供应商，因此必须同步修改现有“仅点击生成时发送”的说明，不能沿用旧数据流承诺。
- 检查失败时保留已生成作品，显示“暂未完成检查”；不能将工具调用失败当成作品质量不合格而自动再付费。
- 自动评价是模型辅助观察。它必须指向具体可见区域，支持“不确定”，用户可修正；不把模糊主观打分包装成客观排行榜。
- 模型实验保留固定照片、固定编译提示和参数快照；单模型 Agent 自适应修改提示的结果不能混作公平横向对照。

## 验收与面试展示

功能与评测材料应覆盖：明确犬种、模糊造型意图、配饰、侧脸、遮挡、多人物、互相冲突的要求、图像 API 失败、检查失败、取消、自动修正次数上限。

每个实验记录至少包含：原图指纹、需求、方案版本、skill 版本、模型、工具调用摘要、调用耗时、输出图像、检查证据、修正理由和最终状态。记录脱敏，图片由用户决定是否保存。

面试演示应能讲清：为什么拆理解与生成、如何设计约束优先级、如何发现 badcase、为什么触发或不触发重试，以及新旧方案的真实对照结果。当前没有这些实测数据，不能预填成功率或成本下降指标。

## 用户参考：localhost:8777

用户认为这个版本“挺有趣味性”，希望简单参考。浏览器实际体验了公开演示模式：上传本项目的虚构示例人像 → 选写实厚涂风 → 点选“戴墨镜，表情嚣张一点” → 演示变身结果。结果明确标注演示，不能作为真实图生图效果证据。

证据：[风格页](design/reference-8777-style.png)、[结果页](design/reference-8777-result.png)。本轮为桌面参考拆解，没有进行该外部参考的移动端验收。

| 观察到的设计 | 趣味来源 | 在本项目中的落地意图 |
| --- | --- | --- |
| “上传照片 → 选风格 → 看变身” | 有明确的开始、选择与揭晓，每屏只做一件事 | 保留阶段节奏；Agent 方案与结果分别就近呈现，不堆出复杂后台 |
| “就这张脸，对吧？”与已上传缩略图 | 文案回应用户刚做的动作 | 让助手围绕当前照片说话，少用接口术语 |
| 写实厚涂、二次元平涂、3D 卡通 | 用户选择的是能想象的形象 | 犬种与画风分别设计，提供有来源的视觉示例和一句话解释 |
| 保守 / 标准 / 自由的改动范围 | 用户控制“能改多少” | 映射成明确的允许改变 / 必须保留字段；背景变更要求与只换头冲突时先处理冲突 |
| 墨镜、棒球帽、开心吐舌等快捷描述 | 不擅长写提示词也能开始玩 | 提供少量可点选灵感，可编辑；Agent 将其转换为一致的造型方案 |
| 结果画布中的原图 / 狗头人滑动对比 | 变化本身成为交互的主角 | 加入键盘可操作的比较控件，图像完整显示，不用聊天消息压缩结果 |
| “换只狗试试 · 同一张脸开盲盒” | 鼓励探索另一种可能 | 可以随机推荐另一犬种，显示目标后再生成；保留已有版本，次数和计费透明 |
| 深色背景、橙色操作、犬类小元素 | 主题性更强，主操作更有能量 | 借鉴情绪和品牌细节；不照搬背景爪印、过多 emoji 或低对比辅助文字 |

修正前文 A 方案：仍保留作品画布与助手，但不强制一开始展示完整左右编辑器。初次体验按阶段展开，助手在造型选择与结果修正时出现；画布和变身体验始终居中。参考不是对新功能、后台鉴权或密钥存储方式的自动授权，相关机制仍单独按产品需求实现。

下一版创作主线建议：**上传照片 → 挑犬种/画风或说一句想法 → Agent 整理造型 → 变身与前后对照 → 换犬种或继续修改**。不确定犬种时可以随机推荐或交给 Agent 提议；保留作者的模型实验入口。
