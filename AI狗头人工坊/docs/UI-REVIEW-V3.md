# 犬种表情与理解模型接入 · 2026-09-13

## 范围和依据

保持摄影工作台与四类绘图适配器；修改用户指出的犬头表情同质化和理解模型接入选择不足。沿用 frontend-design、现有 Radix 控件；内置 image_gen 生成新参考图，真实浏览器执行视觉与交互复核。不新增 UI 工具依赖。

## Critique → 修正

1. 原来八张犬头参考都偏向同一种张嘴吐舌，选犬种难以想象表情差异。重做 24 张同一摄影语言的头像：闭嘴、露舌尖、短圆舌、长舌、偏侧舌与不同嘴型；保留具体犬种毛发、耳形与口鼻辨识。
2. 另外 16 种仅显示相同 Dog 图标，图片与文字条目的密度不一致。全部改为真实参考图，目录统一 64px 头像；桌面双列、手机单列。
3. 原犬种说明只有毛色、耳形，没有解释新图的表情。目录与选中摘要增加具体嘴型说明，手动提示词和 Agent 犬种工具共用同一组建议，明确用户表情要求优先。
4. 三个预设按钮加手填地址会让用户误以为只支持三家。改为供应商和模型两个 Select，自定义兼容入口同级可见；七家厂商按具体型号显示视觉/文字能力。
5. 原说明统一宣称看图与检查，会误导文字模型用户。能力说明紧跟模型选择，文字模式禁用自动修正；创作按钮旁同步真实调用上限和图片发送范围。
6. 新界面第一轮实测发现供应商切换会被 Select 的空值事件清空默认模型。忽略非用户有效选项，复查 MiniMax → DeepSeek 后保留默认视觉型号。
7. 手机弹窗宽度覆盖了基础组件的屏幕留白，长表单贴边。Polish 将最大宽度限制为 viewport - 32px，输入和能力说明统一 16px 垂直间距，模型选择触控高度至少 44px，长表单支持内部滚动和底部保存操作。
