# UI 审查与本地验收

日期：2026-09-12。范围：本地创作、模型接入、模型对比三个页面，及对应服务端适配器。供应商付费实测与公网部署尚未完成，不能把本记录理解为完整上线验收。

## 从设计到实现

项目最初为空；产品定义来自用户确认。先比较轻量创作工作台、趣味影像画廊、专业模型评测台，采用第一个方向，再建立 DESIGN.md、页面骨架和[概念稿](design/studio-concept.png)，随后实现。

核心用户是进行图像创作与模型实验的 AI 产品实践者，面试官可以直接理解演示。最重要的任务是上传人像并生成狗头人；首页直接呈现该任务，不增加营销入口页或虚假 Dashboard。模型配置与多模型实验分别进入独立页面。

## UI Critique 与直接修正

| 具体问题 | 对用户的影响 | 已实施修正与复查 |
| --- | --- | --- |
| 桌面大图居中裁切会切到柴犬耳朵 | 最重要的狗头轮廓不完整，弱化核心效果 | 预览定位调整为 center top，保留自然摄影构图；最终桌面图检查耳朵完整 |
| 模型字段使用额外包装高度，叠加上下间距 | 表单节奏断裂，生成按钮被不必要地推低 | 统一标签结构与字段间距，桌面输入与主按钮对齐且无需卡片包裹 |
| 手机首屏只有输入，没有可见效果 | 初访者还没生成就难以理解核心价值 | 标题说明旁加入小幅、有标签的示例；主按钮仍在 844px 首屏内 |
| 辅助说明多处只有 12px | 格式、状态和隐私提示难读 | 常规辅助文字统一为 13px，正文保持清晰对比；缩略图上的短示例标签单独从简 |
| 手机长弹窗的保存操作可能落到屏幕外 | 填完模型后难以继续 | 弹窗限制高度、正文滚动、底部操作保持可见；复查 390 × 844 |
| 添加/编辑弹窗关闭后焦点落回 body | 键盘用户丢失操作位置 | 记录触发控件并在关闭后恢复；保存与 Escape 均实际测试 |
| 手机对比页标题把“看看”拆开 | 中文阅读停顿不自然 | 按语义使用不拆分的标题片段；终稿两行分别为“同一张人像，”与“看看模型的不同。” |
| 接入空状态最后仅剩“协议”一词 | 形成突兀孤行，破坏留白节奏 | 缩短说明并将四类供应商独立成行，复查手机截图 |
| 移除模型后焦点仍落回 body | 删除行后键盘用户没有合理落点 | 取消时回移除按钮，删除后回添加模型；浏览器读取实际焦点验证 |

上述问题来自实际实现检查；并非对不存在的旧项目捏造缺陷。原始概念方案保留了输入在左、影像在右、单一深绿操作色和连续页面留白。

## 概念稿忠实度检查

最终同时重新查看概念稿与桌面截图，检查以下五个明确锚点：

1. 布局：三入口顶栏、左侧创作表单、右侧大幅效果图保持一致。实现按目标 1440px 画布使用 1200px 容器与 320px 输入列。
2. 字体层级：中文任务标题、简短说明、轻量标签与辅助信息各有层级；使用原生文字，不把概念图当页面背景。
3. 用色：纸白、石墨灰、单一深绿；无渐变、背景光晕或成排装饰卡片。
4. 图像：自然光、绿色外套、人物身体与柴犬头、小幅原图对照保持方向；另行生成对应人像和编辑图，非像素级照搬概念稿中的人物。
5. 控件：克制边框、6px 按钮圆角、独立上传区域、低强调次操作与明确生成按钮；补全实际交互所需的校验和数据流说明。

有意差异：品牌使用统一的 Lucide Dog 图标；手机加入微型效果证明；页脚采用实际导航链接；为触控和可读性采用 44px 操作高度。概念稿用于视觉方向，不承诺逐像素一致。

## 功能验收

| 操作 | 实际结果 / 边界 |
| --- | --- |
| 选择本地人像文件 | 通过真实 filechooser 上传 PNG，显示所选原图，移除预制结果并等待生成 |
| 无模型时开始 | 引导进入模型接入；原图和犬种在页面导航间保留 |
| 添加与编辑 | 缺少密钥显示就近错误；完整模拟配置可以保存；关闭焦点正确 |
| 导入、重复导入、删除 | 导入后提示补密钥；重复配置不新增；移除只删除目标配置 |
| 配置导出与刷新 | 实际下载 JSON 仅含白名单配置；刷新后模型仍在、密钥需重填，运行记录清空 |
| 单次生成 | 独立 8788 模拟服务走真实图片规范化、请求适配和响应解析路径，成功展示 1536 × 1024 PNG |
| 生成中、停止和重试 | 显示实际等待时间；停止转为可恢复状态；重试成功 |
| 多模型部分失败 | A 成功、B 返回模拟 401，成功结果保留；修正 B 后只重试 B，A 不重新调用 |
| 同一输入对比 | 下载 JSON 的两条成功记录具有相同 prompt、规范化 inputHash，并含耗时、尺寸与 adapter 参数 |
| 原图切换与下载 | 结果/原图切换正常；浏览器 download 事件等待未捕获，但实际下载目录获得 3,141,817 字节 PNG，已确认文件落地 |
| 手机结果与配置列表 | 结果各占 342px 内容宽度、纵向排列，模型配置不横向溢出 |
| 生产服务 | npm start 在独立 8789 端口提供前端与 API；全新浏览器页面检查三路由与控制台 |

测试服务不引用生产入口，也不包含真实 API Key；所有模拟密钥均为无效测试字符串。页面编辑期间曾出现开发热更新导致的 Context 暂态错误，完整刷新后恢复；生产验收使用全新页面，避免混入旧开发控制台历史。

## 最终 Polish Pass

- Typography / Spacing / Alignment：统一 32/28px 标题、标签与说明层级；桌面 1200px 容器，手机 24px 左右留白；修复字段间距与中文断词。
- Radius / Border / Shadow：小圆角、必要输入边界；普通区域无阴影，仅浮层使用轻阴影。
- Icons / Hover / Focus：Lucide 图标一致；主次操作有 hover，清晰 focus-visible；添加、编辑、移除弹窗均验证焦点返回。
- Transition / Loading：交互使用短过渡，支持 prefers-reduced-motion；无虚构生成百分比。
- Empty State / Responsive：三页面均有可行动空状态；初始示例与真实输出区分，手机任务顺序重新安排。

最后一轮只修正呈现与键盘焦点，没有增加新的产品功能。

### 实际 Critique 与修正

| 具体问题 | 影响 | 实际修正与证据 |
| --- | --- | --- |
| 桌面操作区过长，CTA 在 900px 外 | 首屏没有明确执行入口 | 折叠质感、模型和修正设置，压缩上传；最终按钮 y812–860，1440×900 可见 |
| 画布比例与 3:2 素材不匹配，灰色留边过大 | 图像失去完整性，界面占位感明显 | 改 3:2 画布与 contain，完整显示照片 |
| 手机先显示长表单，未看到任何效果 | 初次用户难以理解价值 | 说明旁加明确标注的效果缩略图，完整画布在输入之后 |
| 手机主要操作在页面深处 | 调整设置后需要回找按钮 | 固定底部操作与调用提示，留足页尾滚动空间 |
| 质感 ToggleGroup 继承 w-fit，控件宽度不统一 | 视觉密度和对齐破碎 | 展开设置内全宽三等分，同组选中态一致 |

| 展示标题只用系统字体，字距 -0.044em 过紧 | 视觉体系不完整，中文标题过密 | 自托管 Noto Sans SC 600 字体子集，tracking=-0.025em；36/28px |
