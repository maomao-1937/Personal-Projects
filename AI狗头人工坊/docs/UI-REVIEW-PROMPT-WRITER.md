# 模型手填与 DeepSeek 提示词生成器验收

日期：2026-09-14。沿用 V4 的项目工作台、黑白视觉和 Radix 组件，不改变人像变狗头人的核心闭环。

## 本轮设计与实现

- 绘图、理解、提示词模型 ID 均由用户填写。新建留空，切换供应商清空，编辑保留已保存值。地址仍可按协议补全。
- 创作框旁增加「提示词生成器」，设置页提供独立连接入口。DeepSeek 只收到文字、犬种建议与已有提示词，不收到图片。
- 想法 → 一次文字调用 → 可编辑提示词 → 复制或应用。应用只修改创作草稿；设置页应用后返回创作，不直接绘图。
- 连接单独加密保存在服务器，不要求先配置绘图或理解模型。生产环境保存需要管理口令；未保存密钥在关闭时清除。

## Critique → 修正 → 复查

| 具体问题 | 影响 | 修正与证据 |
| --- | --- | --- |
| 供应商选择会带入固定型号 | 用户容易提交自己账户不支持的型号 | 新增 ID 留空、必填验证；浏览器切换四类绘图接口和八个理解供应商均为空 |
| 理解模型依赖预设型号选择器 | 自定义型号入口不直接 | 移除型号下拉，始终显示手填输入；已有 MiniMax 型号仍保留 |
| 首版修改把已知型号的输入能力控件隐藏 | 用户填写视觉型号后仍可能锁在文字模式 | 能力控件始终显示；已知文字型号禁止选视觉，服务端再次校验 |
| 浏览器把模型表单误认成登录表单 | 首次打开时用历史接口地址和密码串填 ID、密钥 | 表单禁用自动填充、输入命名明确，密钥使用 new-password 标记；实际重新加载后 ID 为空且密钥为空 |
| 已生成结果仍有两个近黑主按钮 | 重新生成与应用抢占视觉焦点，容易产生额外调用 | 重新生成降为 outline，应用保留唯一主要操作；桌面与手机截图复查 |
| 重开生成器可能保留旧主输入而忽略新想法 | 实际要求与待生成材料不一致 | 对比外部草稿变化；浏览器验证更新主输入后重新打开能同步，主输入不变则保留未发送想法 |
| 从设置页应用后仍停在设置 | 用户需再找返回入口 | 应用自动返回首页，并检查版本仍为 5、没有新增绘图 |
| 项目恢复完成前生成器曾可点击 | 有可能拿到不完整版本上下文 | hydration 完成前禁用入口；保留现有忙碌状态和过期响应保护 |

## 真实浏览器检查

使用内置浏览器。桌面 1440 × 900，移动 390 × 844；真实页面截图，不使用 CSS 推算代替。

- 正常入口、未连接输入、已保存连接、生成中、可编辑结果、复制、应用和失败保留已执行。
- 测试用独立本地 8788 服务与临时凭据目录。输出持续标为「本地流程测试，非 DeepSeek 实测」，不接触正式连接或供应商。
- 复制内容与编辑值一致；应用只更新草稿，已有 5 个版本未增加。设置页应用返回 `/`。
- 提示词独立连接刷新后可恢复，不需要绘图密钥；失败时保留想法和上一版输出。
- 检查移动单列布局、控件可触达、内容滚动和无横向溢出；原有 Dialog 的关闭和焦点行为沿用并复查。
- 最后精修只调整操作权重、移动间距和输入状态，不增加额外创作步骤。

`npm test`：43 / 43；`npm run build`：通过，仍有既有主 bundle 超过 500 kB 的提示。

新测试覆盖用户模型 ID 原样发送、仅文本请求、空白/截断响应拒绝、供应商错误不回显凭据、保存认证、加密与其他连接共存、刷新恢复、模型不匹配拒绝。浏览器验证使用模拟返回；尚未使用用户有效 DeepSeek API Key 实测连通、费用或提示词质量。本轮没有公网部署。
