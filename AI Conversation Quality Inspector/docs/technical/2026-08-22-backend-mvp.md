# AI 对话质检器后端 MVP 技术与核验记录

## 交付范围

后端采用 Python 3.11、FastAPI、Pydantic、SQLAlchemy、Alembic 和 OpenAI 官方 Python SDK，实现：

- 无注册／登录的邀请码访问；签名 `HttpOnly` Cookie 与 CSRF 双重校验。
- 每个邀请码 50 次成功分析额度；事务预占、成功结算、失败释放、180 秒过期回收和 UUID 幂等保护。
- 销售／客服双场景对话解析，20–12,000 字、最多 200 轮。
- 六个固定维度、逐字证据校验、最多三条主要问题、确定性总分与明确停止联系安全覆盖。
- 匿名有用性反馈与 90 天元数据清理。
- 版本化 API、统一安全错误、请求体限制、CORS、安全响应头和健康检查。

明确不在本阶段实现：账号注册登录、历史报告、原始对话持久化、批量上传和多实例 SQLite。

## 数据与安全决策

数据库表仅有 `invite_codes`、`analysis_attempts` 和 `feedback`。邀请码使用带服务端 pepper 的 HMAC-SHA256 摘要保存。原始聊天、证据、完整结论和建议回复不进入数据库或日志；模型异常统一映射为稳定错误，不向客户端泄露供应商细节。

“一次使用”定义为一次成功完成并通过服务端报告校验的分析。页面打开、邀请码兑换、输入失败、模型失败、结构失败、重复幂等键都不消费额度。

## 运行方式

完整安装、环境变量、迁移、8010 端口启动、邀请码生成和 curl 步骤见 [`backend/README.md`](../../backend/README.md)。默认本地数据库位于 `backend/data/app.db`。正式部署使用 `/tmp/data/app.db` 并固定一个后端实例。生产 SQLite 必须配置 TOS S3 兼容备份；veFaaS 通过函数角色给每个请求注入 STS 临时凭证，首个有效请求在对外 ready 前完成恢复、Alembic `upgrade head` 和首份回读快照，不保存长期 TOS AK/SK。运行中每 300 秒和正常关停前执行在线一致性快照。快照使用不可变对象名、SHA-256、严格 `alembic_version`、必需表和下载回读校验；缺失／损坏备份或超过 600 秒未成功备份时 fail closed，避免静默使用不可恢复的临时盘数据。

## HTTP 验收口径

无 Key 冒烟必须证明：

1. `/health/live` 返回 200。
2. `/health/ready` 返回 200 且 `llm_configured=false`。
3. 没有访问 Cookie 的分析请求返回 401。
4. 正确邀请码可兑换，并得到 50 次余额、Cookie 和 CSRF token。
5. 有效分析因未配置模型返回 503 `LLM_NOT_CONFIGURED`。
6. 失败后访问状态仍显示 50 次。

2026-08-22 本地执行结果：以上六项全部通过。邀请码兑换返回 200 并设置 `HttpOnly` Cookie；有效分析返回 503 `LLM_NOT_CONFIGURED`；失败前后余额均为 50。冒烟使用新建临时 SQLite 数据库和测试邀请码，没有使用真实业务数据。

真实模型冒烟必须另外记录模型 ID、耗时、是否重试、六维结构、证据逐字匹配、风险提示、限制说明和建议回复质量。未提供 Key 时不得把假模型测试标记为真实验收通过。
