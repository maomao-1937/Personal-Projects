# 前端技术适配声明

- 日期：2026-08-29
- 阶段：正式前端阶段，代表页实施前
- 依据：PRD V1.1、后端核验结论、4i 现有拆解证据、《AI Agent 产品 Vibe Coding 通用前端技术栈手册》、`ui-ux-pro-max`

## 1. 适配结论

现有 `frontend/` 是 Vite + React JavaScript 的旧版单页界面，面向“上传音乐与视频后自动卡点”的历史链路。它不具备正式产品所需的项目路由、TypeScript strict、Storyboard / Cut / Preview / Export 工作区、任务恢复和版本失效表达。

正式前端将保留仓库内可复用的构建经验，但前端应用技术底座调整为：

- Next.js App Router；
- TypeScript strict；
- Tailwind CSS + 语义化 CSS Variables；
- Lucide 图标；
- 原生 Fetch 封装的统一 API Client；
- 后端 Job 快照 + SSE 事件流；
- 真实浏览器验收和自动化检查。

该调整符合用户已经确认的正式前端技术栈，不改变已核验后端能力。

## 2. 后端适配原则

- FastAPI `/api/v1` 是唯一业务接口来源；
- 后端资源、Job、Timeline Version、Preview、Export 状态是唯一事实来源；
- 不把任务状态仅保存在 React 内存；
- 所有昂贵任务提交使用 `Idempotency-Key`；
- SSE 断开后基于事件序号恢复，失败时降级轮询；
- 不因旧 Artifact 或旧 Export URL 存在而显示当前版本已完成；
- Cut 重新生成后按后端返回的版本关系标记 Preview / Export 过期；
- 前端不直接调用 Storyboard、视频或 ASR 模型 Provider。

## 3. 状态管理适配

状态按职责拆分：

- URL 状态：项目 ID、当前页面、选中 Scene / Cut；
- Server State：Project、Analysis、Storyboard、Cuts、Timeline、Preview、Export、Jobs；
- 本地 UI 状态：抽屉、弹窗、未提交表单、播放器状态；
- 用户偏好：仅保存不影响业务事实的界面偏好。

P0 不引入全局状态框架作为默认方案。先使用 Next.js 路由、Server Component 边界和小范围 Client State；只有真实复杂度出现后再增加依赖。

## 4. UI/UX 适配

`ui-ux-pro-max` 对视频工作区给出的有效建议是：深色媒体区域、高密度后台布局、明确状态色、可见焦点、至少 4.5:1 对比度、44 × 44 px 触摸目标、轻量动效和 reduced-motion 支持。

检索结果中的 Hero-Centric Landing Pattern 与本项目编辑工作区不匹配，明确不采用。最终采用用户确认的混合方向：

- 4i 可观察的信息架构和操作路径；
- 深色视频 / 音频上下文区；
- 浅暖色 Storyboard 与编辑面板；
- 自有紫蓝品牌色；
- 成功、运行、等待、失败、过期分别编码；
- 不复制 4i 品牌、素材、原文案和未验证功能。

## 5. 路由与组件适配

使用 App Router 文件路由，并优先将页面专属组件放在对应路由的 `_components/` 中。稳定跨页面复用的外壳、任务状态、API Client 和基础 UI 才进入共享目录。

首个代表页为 `/projects/[projectId]/storyboard`，它将建立：

- App Shell；
- Project Progress；
- Audio / Waveform / Beat 上下文；
- Scene Navigator；
- Cut Card 与 Cut Inspector；
- Job 状态和恢复机制；
- Preview 版本状态条。

## 6. 安全适配

- 模型 API Key、Provider Base URL 和内部配置不得进入前端 Bundle；
- 浏览器只持有后端签发的会话信息；
- 不把 Key 写入仓库、README、日志、错误提示或浏览器可读环境变量；
- 只有 `NEXT_PUBLIC_` 的非敏感运行时地址可以暴露给客户端；
- 下载通过后端授权 Artifact 接口完成。

## 7. 质量闸门

每一阶段至少验证：

- ESLint；
- TypeScript strict typecheck；
- 单元 / 组件测试；
- Next.js production build；
- 390、768、1280、1440 四档真实浏览器检查；
- 键盘、焦点、对比度、加载和错误状态；
- 与真实后端联调，不以 Mock 成功代替闭环验收。

## 8. 当前不执行

- 不部署；
- 不接入新模型；
- 不修改后端 Provider；
- 不开发 P1 能力；
- 不在代表页确认前扩展全站。

本声明与正式前端设计规格确认后，才生成可执行的《分阶段前端开发文档》并开始代表页实现。代表页通过人工确认后，才扩展完整主链路。
