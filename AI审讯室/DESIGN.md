# AI 审讯室设计系统

## 设计命题

**一份仍在推进的案卷，而不是暗色聊天机器人。**

视觉借用刑侦档案、审讯记录、物证封条和单向玻璃的真实语言。案件库负责选择，工作台负责判断，对话负责推进；每一块信息都必须回答“我现在知道什么、下一步能做什么”。

## 色彩

| Token | 值 | 用途 |
|---|---:|---|
| `--ink-950` | `#070807` | 页面背景 |
| `--ink-900` | `#0D0F0E` | 工作台主面 |
| `--ink-850` | `#131614` | 抬升区域 |
| `--line` | `#2A2E2B` | 结构分隔 |
| `--paper` | `#E9E4D8` | 主文字/档案纸 |
| `--muted` | `#989B94` | 次要信息 |
| `--amber` | `#C79A51` | 唯一主操作与当前选择 |
| `--rust` | `#9B4A3F` | 矛盾、警告、失败 |
| `--green` | `#7E9A82` | 已确认、已完成 |

禁止蓝紫 AI 渐变、霓虹光晕、玻璃拟态、大面积纯红和无意义装饰。

## 字体

- 叙事标题：`Songti SC`, `STSong`, `Noto Serif SC`, serif。
- 操作正文：`PingFang SC`, `Microsoft YaHei`, `Noto Sans SC`, sans-serif。
- 案号与状态：`SFMono-Regular`, `JetBrains Mono`, monospace。
- 首页主标题 56–88px；页面标题 32–48px；正文 14–16px；状态标签 10–12px。
- 嫌疑人口供用宋体，玩家提问用无衬线，规则裁定用等宽状态行，不依赖气泡颜色区分。

## 布局

### 首页

单屏完成定位与进入：左侧一句产品承诺和单一主 CTA，右侧是可操作的当前案卷。首页不堆营销卡片。

### 案件库

一个主推案件占据视觉中心，其余案件以档案列表展示。自定义生成放在次级入口，生成中保留进度解释和取消/降级路径。

### 调查工作台（Desktop 1440×900）

```text
┌ 案号 / 剩余提问 / 结案 ───────────────────────────────┐
│ 嫌疑人列  │      当前审讯记录与输入      │ 证据 / 时间线 │
│ 220–260   │        minmax(0,1fr)        │   320–360    │
└──────────────────────────────────────────────────────┘
```

- 中间审讯区永远是最大视觉主体。
- 左侧嫌疑人列显示人物、身份、压力状态和未处理矛盾，不出现数值血条。
- 右侧一次只显示证据、案情或时间线中的一种；选中证据后输入区必须明确显示“正在出示”。
- 顶部只保留案件号、问题额度、当前阶段和结案动作。

### Mobile 390×844

- 嫌疑人横向选择条位于顶部，当前人物固定可见。
- 内容区只呈现当前审讯；证据、案情、时间线通过底部工具抽屉切换。
- 输入区贴近底部安全区，触控目标至少 44px；不复制桌面三栏。

## 形状与层级

- 页面结构圆角 0–2px；输入与抽屉 6–8px；档案纸 8px。
- 主要层级靠一像素边界、底色和留白，不靠卡片阴影。
- 阴影仅用于真正覆盖内容的抽屉、对话框和纸质案卷。
- 每屏最多一个实心琥珀色主按钮。

## 组件规则

- Button：主按钮 48–52px 高；Focus 使用 2px 琥珀色轮廓和 3px offset。
- Input：深色实面，错误就地说明；发送时保留问题草稿直到服务端确认。
- Suspect selector：显示姓名、身份和心理状态；切换不得清除其他嫌疑人的记录。
- Evidence：显示编号、来源、描述、发现状态；锁定证据不泄露名称和内容。
- Transcript：每条记录包含人物、回合、策略和证据引用；系统裁定永久留在对应回合。
- Report：嫌疑人、动机、手法、证据链分步但保留全局进度；提交前明确不可逆。
- Result：先给是否成立，再解释证据链和遗漏；不得用纯分数代替复盘。

## 动效

- 页面进入 180–260ms；面板切换 140–180ms；只动画 opacity 和 transform。
- 不使用强制黑场、落笼、逐字解密或无法跳过的开场。
- 新证据只做一次短促高亮；矛盾命中使用边界与文字变化，不全屏闪红。
- `prefers-reduced-motion` 下关闭位移和环境动画。

## 状态

- Loading：解释正在建立案件、正在等待嫌疑人回答或正在封存报告。
- Empty：告诉玩家还需问什么或如何发现第一条线索。
- Error：说明失败边界，并提供重试、使用精修案件或返回案件库。
- Disabled：按钮旁解释缺少的条件，不让用户猜。
- Offline/模型失败：使用服务端安全回复继续当前案件，不改变规则状态。
