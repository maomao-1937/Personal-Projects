# PRD 到产品：推导方法论

如何把一份 PRD（或点子、方向）变成生产级 Agent 产品。这是 `BLUEPRINT.md` 中五步 SOP 的详细方法论。

## 推导管线

```
PRD → ① 拆解 → ② 建模 → ③ 选型 → ④ 设计 → [确认] → ⑤ 代码
```

每一步的产出是下一步的输入。绝不跳过，绝不假设。

---

## 第一步：需求拆解

从 PRD 提取**硬事实**。填下面这张表。填不上的必须标注 **"待确认"** —— 这是不可协商的。"待确认"是要问用户的问题，不是用想象填的空。

| 维度 | 问题 | PRD 中的出处 |
|---|---|---|
| 目标 | 产品要完成什么？可量化的成功标准？ | |
| 用户 | 谁用？同步还是异步？人机比？ | |
| 核心闭环 | 一次完整的"输入 → 行为 → 交付物"循环 | |
| 交付物 | 代码？文档？决策？操作？ | |
| 边界 | 绝对不能做什么？红线？ | |
| 约束 | 时延、并发、合规、成本、可用模型 | |

### 必须立即暴露的危险信号

- PRD 描述的是僵化的逐步工作流 → 可能根本不需要 Agent，质疑它。
- PRD 说"AI 会做一切" → 追问边界和失败模式。
- PRD 没有可度量的成功标准 → 追问"怎么知道它成了"。
- PRD 引用 10+ 个外部系统 → 追问哪些是 v1 真正必需的。

---

## 第二步：领域建模

把每个事实映射到 Harness 五要素。产出产品的**领域骨架** —— 整个推导中最重要的产物。

```
工具     ←  交付物需要什么外部动作
知识     ←  模型必须访问什么领域专长
观察     ←  如何确认动作产生了预期效果
行动     ←  这些动作的形式（API/CLI/UI/消息）
权限     ←  什么需要审批，什么数据不能碰
```

### 示例：一个"工单分诊 Agent"

- **工具**：获取工单、查询知识库、创建升级单、回复客户
- **知识**：产品文档、升级策略、SLA 规则、回复模板
- **观察**：工单状态变化、知识库搜索置信度、回复送达确认
- **行动**：对工单系统和知识库的 REST API 调用
- **权限**：客户数据只读；升级需审批；禁止退款操作

---

## 第三步：组件选型

用架构决策表。**默认答案是"除了 agent loop + 工具，什么都不加"。** 只有 PRD 要求时才加组件。

对每个候选组件问：**"没有它产品会怎样？"**
- 答"没变化" → 删掉。
- 答"会失败" → 保留。
- 答"不确定" → 标"待确认"并问用户。

参考实现在仓库 `s01`–`s17`，每个组件一个可运行的 `code.py`。

## 第四步：架构设计（先交付这一步）

方案文档必须包含以下全部内容。**这是用户确认的对象，确认前不写任何代码。**

1. **五要素清单** —— 来自第二步
2. **组件选型表** —— 选了哪些 / 为什么 / 放弃了哪些
3. **模块划分与数据流** —— 一张图 + 一段说明
4. **工具清单** —— 每个工具：名称、输入、输出、副作用、权限
5. **系统提示词草案** —— 身份 + 规则 + 工具 + 知识目录
6. **上下文与记忆策略** —— 会话内 + 跨会话
7. **安全与降级** —— 谁能做什么，失败怎么办
8. **可观测性** —— 日志、指标、轨迹采集
9. **技术栈与部署形态** —— 进程 / 服务 / 团队

### 系统提示词草案模板

```
你是 {身份}。你通过 {核心闭环} 帮助 {用户} 达成 {目标}。

规则：
- {规则 1：边界}
- {规则 2：质量底线}
- {规则 3：升级条件}

可用工具：{工具列表及一句话说明}

知识：{有什么知识，如何按需加载}

完成时：{交付物定义}。
无法继续时：{降级路径}。
```

## 第五步：代码生成（确认后）

三层，按顺序：

**第一层 —— 骨架**（几分钟内可运行）
- agent loop + 3~5 个领域工具 + 系统提示词
- 证明核心闭环端到端跑通

**第二层 —— 硬化**（可靠）
- 错误处理、超时、重试、日志、配置外置
- 权限检查、路径安全、默认拒绝
- 可观测：结构化日志 + 轨迹采集

**第三层 —— 产品化**（可交付）
- 集成选中的组件（记忆/任务/团队/MCP）
- 测试：单测（循环、分派）、边界测试（权限、安全）
- 部署脚本 + README + 指标

---

## 验收：Demo vs 生产

| 维度 | Demo | 生产 |
|---|---|---|
| 运行 | 手动步骤 | 一条命令 |
| 错误 | 忽略 | 降级路径 |
| 可观测 | print() | 日志 + 指标 + 轨迹 |
| 配置 | 硬编码 | 外置 |
| 测试 | 无 | 单测 + 边界测试 |
| 部署 | "我机器上能跑" | 有文档的部署形态 |
| 成功 | "看起来对" | 可度量的指标 |

一个产物只有满足右列全部，才算生产级。
