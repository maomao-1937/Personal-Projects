# AI 审讯室设计规格

> 版本：v1.0 确定性 Demo  
> 输入：`AI审讯室-竞品参考PRD.md`、重建的 `REFERO-FACTORY-DESIGN.md`、Refero Factory 页面实测、三份通用手册。

## 1. 核心游戏循环

```text
阅读固定案件档案
→ 选择审讯策略与至多 1 条证据
→ 输入自由问题
→ 后端规则判断问题主题、证据命中、重复与策略影响
→ 嫌疑人用预设模板进行 2–4 句临场回应
→ 更新证据、心理状态与侦探笔记
→ 第 3–8 回合间主动结案
→ 三步报告
→ 确定性评分与完整真相复盘
```

嫌疑人局部承认不会自动结束；游戏的最终动作始终是玩家提交报告。

## 2. 页面和路由

| 路由 | 页面 | 主要任务 |
| --- | --- | --- |
| `/` | 落地页 | 解释价值并创建免费 Session |
| `/case/001/briefing` | 案件简报 | 阅读事件、嫌疑人、公开证据和任务 |
| `/case/001/interrogate` | 审讯工作台 | 完成最多 8 回合的核心博弈 |
| `/case/001/report` | 三步结案报告 | 选择真相、证据、动机与手法 |
| `/case/001/result` | 结果与复盘 | 查看分数、真相、命中与遗漏 |

Session ID 使用查询参数和 Local Storage 共同恢复；URL 优先，Local Storage 只保存 ID，不保存或冒充业务状态。

## 3. 案件、回合、证据、心理状态和结案状态

- 案件：CASE-001 固定真相、时间线、5 条证据、3 个谎言节点与结构化答案。
- 回合：最多 8 回合；玩家消息立即出现；请求中锁定输入；失败保留问题。
- 证据：`public`、`discovered`、`selected`、`effective`、`used_ineffective`。卡片只陈述事实。
- 心理状态：只显示镇定、戒备、动摇、濒临崩溃，不显示防线数值或血条。
- 结案状态：第 3 回合前可见但禁用；还需至少 2 条已发现证据与 1 次有效命中；第 8 回合后自动导航到报告。
- 报告：三步完成，提交前确认；返回审讯不扣回合；提交后以后端结果为准。

## 4. 桌面审讯工作台布局

```text
┌──────────────────────────────────────────────────────────────┐
│ CASE-001 / 案件名      回合 03/08   状态：动摇   [提交结案] │
├───────────────────┬──────────────────────────────────────────┤
│ 案件简报           │ 嫌疑人身份 / 当前状态                    │
│ 公开事实           ├──────────────────────────────────────────┤
│                   │ 对话记录（主阅读区，aria-live）           │
│ 证据文件           │                                          │
│                   │                                          │
│ 侦探笔记           ├──────────────────────────────────────────┤
│ 320–380 px         │ 策略 / 已选证据 / 输入 / 发送            │
└───────────────────┴──────────────────────────────────────────┘
```

- 工作台占据视口主体；右侧对话区独立滚动。
- 输入区在右侧布局底部，不使用覆盖式 `position: fixed` 遮挡消息。
- 左栏证据卡可直接键盘选择，已选证据在输入区形成可移除的条目。

## 5. 移动端布局

```text
┌──────────────────────┐
│ 03/08  动摇  [结案]  │
├──────────────────────┤
│ 嫌疑人摘要            │
│                      │
│ 对话主视图            │
│                      │
├──────────────────────┤
│ [档案] [证据] [笔记] │ ← 底部抽屉入口
│ 策略横向滚动          │
│ 输入            发送  │
└──────────────────────┘
```

- 360 px 不横向滚动；触控目标至少 44 px。
- 档案、证据和笔记进入同一底部抽屉，用标签切换。
- 输入区使用 `sticky` 底部布局并考虑安全区域；不依赖 hover。

## 6. Factory 视觉系统的适配方式

- 保留：黑色画布、深灰工作面、灰米白亮卡、细边框、低圆角、无阴影、等宽标签和机械动效。
- 改造：终端仪表盘变为审讯记录；亮色白卡变为卷宗；状态信号变为证据作用和心理变化。
- 不复制：品牌、Logo、原站文案、资产、代码终端、交通灯、专有字体、像素级布局。
- 视觉记忆点：每次有效命中后，一枚克制的暗红「矛盾已记录」章短促落在侦探笔记中。它只在事件发生时出现一次。
- 自检：黑色 + 米白本身容易落入通用暗色模板，因此所有结构标签都使用真实审讯语义；页面不出现开发者、构建、终端和指标仪表盘词汇。

## 7. 颜色、字体、间距、边框和圆角令牌

```css
:root {
  --canvas: #101010;
  --panel: #1D1A18;
  --panel-secondary: #252220;
  --border: #3D3A39;
  --text: #EEEEEE;
  --muted: #8A8380;
  --tertiary: #B8B3B0;
  --file-paper: #EEEEEE;
  --file-ink: #101010;
  --selected: #86A995;
  --effective: #A65050;
  --ineffective: #A18F69;
  --error: #D45B5B;
  --radius-control: 3px;
  --radius-card: 8px;
  --radius-panel: 12px;
}
```

- 字体：中文正文使用系统无衬线；编号与状态使用等宽字体；档案和报告标题少量使用中文宋体。
- 间距：8 px 基础节奏；控件 8–12 px 内边距；卡片 16–24 px；工作台区域间隔 24 px。
- 边框：统一 1 px；焦点使用 2 px 外轮廓；不使用阴影。
- 标题：字重 400/500，中文不使用极端负字距。

## 8. 动画规则

- 时长 150–200 ms，缓动 `cubic-bezier(0.4, 0, 0.2, 1)`。
- 允许：边框和状态色切换、有效证据一次闪烁、嫌疑人回答淡入、档案章落下、抽屉展开、按钮提交态。
- 禁止：弹簧、视差、无限漂浮、长 glitch、发光、扫描线、逐字解密和页面抖动。
- `prefers-reduced-motion: reduce` 时取消非必要过渡与关键帧。

## 9. 可访问性

- 使用 `button`、`form`、`label`、`dialog` 和标题层级等语义元素。
- 策略与证据支持 Tab、Space 和 Enter；所有焦点清晰可见。
- 对话区 `aria-live="polite"`，思考状态使用 `role="status"`，但不逐字朗读。
- 状态文字与图标并存，不只用颜色。
- 错误靠近输入框，发送失败保留内容。
- 对话框锁定焦点、Esc 可关闭、关闭后焦点回到触发按钮。
- 1366 × 768 下确认按钮无需页面外滚动；移动抽屉内容可滚动、操作栏固定可见。

## 10. 前端确定性 Demo 规则

- 前端不包含命中映射、防线增减和评分公式；这些规则只由 FastAPI 执行。
- 前端通过 `/api/v1` 获得公开案件、Session、回合结果和评分结果。
- 本地预设回答不模拟随机性：相同 Session 状态和相同输入产生同类确定性反馈。
- 发送时立即乐观显示玩家问题，但以后端响应确认回合；失败时撤销占用回合并保留输入。
- 报告选项全部为结构化 ID；前端不推断正确答案。
- 结果页无论成败都展示后端返回的完整真相。
- 复制分享文案只包含案件名、等级、分数和回合数，不含真相字段。
