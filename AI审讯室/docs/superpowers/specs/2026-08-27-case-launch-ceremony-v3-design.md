# AI 审讯室案件启动仪式 V3 设计规格

日期：2026-08-27  
状态：视觉、灯光、文案与实现边界已获用户确认，等待书面规格复核

## 1. 目标

重做 AI 审讯室首页的背景主题与案件启动仪式，使首页成为一幕完整、克制的黑暗叙事场景，而不是由 CSS 渐变、光锥和装饰文字拼成的深色落地页。

页面的唯一任务是让用户理解产品用途并启动案件生成。视觉核心是一个位于黑暗空间中央的正面收容装置：点击前正面敞开，点击后金属栅门落下并锁闭，随后舱内顶灯照亮身份模糊的 AI 嫌疑人。

## 2. 非目标

- 不复刻任何参考网站的具体镜面、人物、场景或 WebGL 效果。
- 不制作真人写实角色、清晰正脸、明显性别特征或肢体动画。
- 不制作完整可见的传统警局、审讯桌或写实牢房。
- 不引入 WebGL、Three.js、背景视频或 3D 实时渲染。
- 不增加系统编号、版本号、虚假百分比、技术日志或多行状态面板。
- 不改变既有案件生成 API、后续简报流程或 4 秒并行状态机约束。

## 3. 参考案例与转化原则

### 3.1 主要参考

- [La Dernière Danse](https://ladernieredanse.ronin161.com/)：采用其“中央实体装置是进入下一幕的入口”这一空间逻辑，不采用镜面、女性角色或原站交互。
- [Genesis Noir — Busk ’til Dusk](https://www.awwwards.com/sites/genesis-noir-busk-til-dusk)：采用单场景叙事、单一主光源、前景遮挡和极少环境线索。
- [Joshua’s World](https://www.joshuas.world/)：采用简化形体、半写实插画材质与有限色组，不采用其森林或机器人元素。
- [Nothing to Watch](https://recent.design/i/6wmr7uw-nothing-to-watch)：采用中央主体承担品牌记忆、UI 退到画面边缘的克制层级。

### 3.2 转化结果

V3 不是“另一种暗色背景”，而是把首页改造成一个具有前景、中景和背景关系的封闭空间。中央收容装置承担品牌记忆；人物、灯光和文案均围绕它服务。

## 4. 空间构图

### 4.1 桌面构图

```text
┌─────────────────────────────────────────────────────────────┐
│ AI 审讯室                                                    │
│                                                             │
│                   中央固定收容舱           右后方冷光源      │
│   一句产品说明      ┌─────────────┐             ╲            │
│                    │   AI 嫌疑人   │              ╲           │
│   生成案件 →       │   坐姿侧影    │       右侧近景审讯者      │
│                    └─────────────┘       背部与肩部剪影      │
└─────────────────────────────────────────────────────────────┘
```

- 收容舱位于画面中心，占桌面视口约 `46–52vw` 宽、`70–76vh` 高。
- 收容舱正面朝向用户，但展示顶部、右侧内壁与地面基座的浅纵深，避免成为平面方框。
- 固定外框包含顶部机械槽、厚重侧框、内壁、基座与中央锁扣位置。
- 待机时收容舱正面敞开；点击后落下的是前方金属栅门，而不是再次落下一整座牢笼。
- 嫌疑人坐在舱内中下部，只占内部高度约三分之一，保持 30–45° 侧向、低头和面部隐没。
- 审讯者位于右侧近景，只展示背部、肩部和少量侧轮廓，约遮挡画面宽度的 18–22%。
- 审讯者与嫌疑人形成接近一条斜线的视线关系，但不可完全重叠。
- 左侧保留完整负空间，仅承载品牌、一句话和启动入口。

### 4.2 背景

- 背景不是完整可辨认的警局或牢房，而是一处近乎被黑暗吞没的封闭空间。
- 只保留极弱的粗糙墙面、地面接缝、少量雾气和收容舱接地阴影。
- 背景细节负责证明空间存在，不得形成第二视觉中心。
- 超宽屏只延展左右黑暗区域，不拉伸收容舱或人物。

### 4.3 视觉焦点顺序

1. 中央收容装置及其光域
2. 舱内 AI 嫌疑人
3. 右侧近景审讯者
4. 左侧产品说明和启动入口

## 5. 人物设计与观看舒适度

### 5.1 AI 嫌疑人

- 成年但无法判断性别，身材比例中性。
- 宽松、直筒、无性别指向的深色服装。
- 侧身低头，面部至少 75% 位于阴影中，不显示清晰眼睛和完整五官。
- 安静坐在金属凳上，不捆绑、不受伤、不表现恐惧或疼痛。
- 顶灯开启后仅出现少量扫描断层、微弱数字噪点或离散节点，说明其 AI 身份。
- 人物本身没有动作，只通过透明度从 `0` 渐显至约 `0.85`。

### 5.2 审讯者

- 同样保持中性体态，不展示正脸。
- 使用宽松直线型外套或制服轮廓，不出现警徽、武器或现实机构标识。
- 仅作为前景遮挡、尺度参照和视线引导，不得比中央收容舱更亮。

### 5.3 舒适度约束

- 不使用全屏高频闪白。
- 不出现暴力、伤痕、束缚器具或真人受刑暗示。
- 冷光闪烁仅影响灯具、局部光束和有限反射面。
- 暖光不照出清晰五官。
- 支持 `prefers-reduced-motion`，减少动态模式跳过闪烁和落栅门，只保留状态渐变。

## 6. 图层与材质

V3 使用半写实动漫场景图层与少量 DOM 动画，不使用实时 3D。

图层从后到前为：

1. `环境底图`：黑暗空间、固定收容舱外框、地面、顶部机械槽；不含人物、栅门、文字和激活光。
2. `嫌疑人图层`：透明背景的中性坐姿侧影。
3. `冷光图层`：右后方冷灰灯具、斜向局部光束、人物边缘光与空气散射，因此合成在嫌疑人上方、审讯者下方。
4. `栅门图层`：独立正面金属栅门，可执行垂直下落、微回弹和锁闭。
5. `暖光图层`：舱内顶灯、窄光锥、人物边缘光与小范围地面光池。
6. `审讯者图层`：透明背景的右侧近景背影。
7. `极轻颗粒与暗角`：统一各图层，不承担主要空间塑造。
8. `文案和状态层`：保持真实 HTML 文本与按钮。

人物、环境和光照图层需要共享同一透视、镜头高度和落点。任何光线都必须能追溯到画面内的灯具或机械装置。

## 7. 色彩系统

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 空间黑 | `#020303` | 页面与背景主黑位 |
| 焦黑墙体 | `#080A0B` | 极弱空间纹理 |
| 金属暗面 | `#141718` | 收容舱和栅门主材质 |
| 冷灰灯 | `#C5CBD3` | 待机斜向背光，仅局部使用 |
| 3000K 暖白 | `#FFE8D6` | 锁闭后的舱内顶灯核心 |
| 警戒暗金 | `#D9A74A` | 锁扣完成态与“真相”文字 |
| 主文字 | `#D8D5CF` | 产品说明与按钮 |
| 变化冷灰 | `#758089` | 艺术字缓慢变色阶段 |
| 变化暗红 | `#7B4A48` | 艺术字缓慢变色阶段 |

暖光只能存在于收容舱内部和极小地面区域；冷光只能存在于待机阶段的右后方。禁止大面积灰雾和无来源的全屏泛光。

## 8. 精确状态机与时间线

生命周期保持：

```text
IDLE → CEREMONY → GENERATING? → LOCKING → COMPLETED
                         ↘ ERROR
```

- 点击后 `100ms` 内发起案件生成请求，动画与请求并行。
- `CEREMONY` 固定持续 `4.0s`，正常模式不可重复触发。
- 请求早于 `4.0s` 返回时，等待仪式完成后进入 `LOCKING`。
- 请求晚于 `4.0s` 返回时，平滑停留在 `GENERATING`，保持栅门锁闭与暖光稳定。
- `LOCKING` 持续 `0.5s`，然后触发完成回调并进入案件简报。

### 8.1 0.00–4.00 秒

| 时间 | 表现 |
| --- | --- |
| `0.00–0.25s` | 按钮按压反馈；主文案与启动入口透明度归零 |
| `0.25–1.25s` | 右后方冷光发生三次低强度、不规则失压闪烁，并彻底熄灭；不影响整个屏幕 |
| `1.25–1.55s` | 300ms 黑场停顿，只允许极弱装置轮廓 |
| `1.55–2.75s` | 收容舱顶部机械槽打开，正面栅门以重力加速曲线落下 |
| `2.75–3.15s` | 栅门触底产生 `3px → 2px → 1px` 微回弹，中央锁扣闭合 |
| `3.15–3.65s` | 舱内 3000K 暖白顶灯通电，窄光锥和小范围地面光池渐显 |
| `3.65–4.00s` | AI 嫌疑人透明度渐显至约 `0.85`，少量 AI 扫描断层同时出现 |

### 8.2 GENERATING

- 固定收容舱、栅门、锁扣和暖光保持不动。
- 嫌疑人没有动作，仅允许极慢噪点呼吸。
- 底部单行轮换真实生成阶段文案。
- 禁止再次执行冷光闪烁或栅门下落。

### 8.3 LOCKING

- AI 噪点立即停止。
- 锁扣边缘在约 `260ms` 内转为 `#D9A74A`，不得大面积亮黄。
- 中央出现：

```text
TRUTH LOCKED
真相已封存
```

- 停留 `0.5s` 后进入案件简报。

## 9. 文案与界面层级

### 9.1 固定文案

品牌：

```text
AI 审讯室
```

产品说明：

```text
用 8 次提问，审讯一个会撒谎、却无法改写真相的 AI 嫌疑人。
```

启动入口：

```text
生成案件  →
```

### 9.2 艺术字

- “会撒谎”和“AI 嫌疑人”在低饱和冷灰与暗红之间缓慢变化。
- “真相”始终使用低饱和暗金色。
- 颜色变化只发生在文字填充内部，不使用霓虹外发光。
- `prefers-reduced-motion` 下停止颜色流动，使用固定中间色。

### 9.3 启动入口

- 不使用巨大实心按钮或独立卡片。
- 使用细边框、深色半透明底和右侧箭头的文字操作条。
- 悬停只允许轻微边框提亮和箭头平移。
- 点击后立即禁用并退出，防止重复请求。

### 9.4 状态文案

- 只显示一行真实阶段文案，例如“正在构建嫌疑人行为模型…”。
- 不显示虚假百分比、多行清单、版本号或系统日志。
- 错误时在原启动入口位置显示明确原因和“重新生成案件”。

## 10. 响应式规则

### 10.1 桌面与超宽屏

- 主艺术板按 `16:9` 构图。
- 收容舱保持画面中央，人物和锁扣不随超宽屏向两侧漂移。
- 超出艺术板的区域使用空间黑延展。

### 10.2 平板

- 收容舱宽度约为 `58–66vw`。
- 审讯者只保留背部和单侧肩膀，避免覆盖启动入口。
- 产品说明允许两到三行，不缩小到不可读尺寸。

### 10.3 手机

- 采用独立竖屏裁切规则，不直接缩小桌面构图。
- 收容舱宽度约为 `78–84vw`。
- 审讯者缩减为右下角局部肩部轮廓，不能遮住嫌疑人和锁扣。
- 文案位于左上至中部安全区域，避开设备刘海与底部手势条。
- 启动入口触控高度至少 `44px`。
- 页面不得出现横向滚动、人物裁断关键部位或文字覆盖嫌疑人。

## 11. 性能、可访问性与失败处理

- 场景图层优先输出 WebP 或 AVIF，并按桌面、平板和手机加载合适尺寸。
- 开始前预加载栅门、暖光和嫌疑人图层，避免演播过程中空白或闪图。
- 图片必须声明宽高或固定比例，防止布局跳动。
- 主按钮具备清晰键盘焦点；文字与背景满足可读对比度。
- `aria-busy` 反映案件生成状态，生成文案与封存结果使用适当的状态播报。
- 网络失败不跳出场景；在原按钮区域提供一次明确重试入口。
- 页面卸载时清理 GSAP Timeline 和轮询请求，避免重复回调。

## 12. 验收标准

### 12.1 视觉

- 第一眼识别中央收容装置，而不是背景纹理、审讯者或文案。
- 待机画面能看出收容舱正面敞开，点击后只落下前方栅门。
- 所有灯光都有可见或可推断的光源，背景不再呈现大面积浅灰渐变。
- 嫌疑人没有可辨认正脸和明显性别特征，并保留轻微 AI 身份线索。
- 画面不出现暴力、束缚或现实执法机构标识。

### 12.2 交互

- 请求在点击后 `100ms` 内发起。
- 快速请求不会提前跳过 4 秒仪式。
- 慢速请求在 4 秒后稳定停留于 `GENERATING`。
- 栅门和冷光序列只播放一次。
- `LOCKING` 保持约 `0.5s` 后才进入简报。
- 重复点击不会产生第二个生成请求。

### 12.3 响应式与质量

- 桌面、平板和手机五档视口无横向溢出。
- 手机端嫌疑人、锁扣、启动入口均保持可见。
- 减少动态效果模式无闪烁和快速下落。
- 类型检查、代码检查、组件测试、状态机测试、生产构建和完整前后端冒烟测试通过。

## 13. 开发范围

开发阶段只修改案件启动首页所需的场景资产、组件、样式、状态测试和视觉回归测试。不得顺带重构案件简报、审讯、报告或后端生成业务。
