# AI 审讯室首页电影化案件启动设计

## 1. 背景

AI 审讯室已经上线并具备完整的访问验证、案件生成、固定案回退、审讯、结案和结果复盘流程。当前首页采用「左侧营销文案 + 右侧审讯工作台预览 + 下方流程说明」的常见产品落地页结构，能够说明功能，但容易被理解为 AI SaaS 或后台管理系统，未能在首屏建立足够强的审讯关系、悬疑感和案件启动仪式。

本轮只重构首页的视觉和交互表现，不修改案件生成规则、API、数据结构、Session、登录、审讯、结案、数据库或部署配置。

## 2. 设计目标

新版首页应在用户点击前后完成一个连贯的视觉叙事：

1. 用户进入一个尚未启动的审讯空间。
2. 站立的审讯者遮挡后方光线，坐着的 AI 嫌疑人部分隐藏在阴影中。
3. 用户点击「生成案件」。
4. 后方光线闪烁并熄灭，机械封存框架落下。
5. 暖白顶灯照亮 AI 嫌疑人，案件继续生成。
6. 生成完成后，嫌疑人和案件事实停止变化，显示「真相已封存」。
7. 页面自动进入现有案件简报流程。

用户应在 10 秒内理解：

- 这是一个 AI 审讯推理游戏。
- 玩家只有 8 次正式提问。
- AI 嫌疑人可能撒谎。
- AI 无法改写已经生成并封存的案件事实。

## 3. 非目标

本轮不做以下事项：

- 不重构后端、数据库或 API Schema。
- 不修改接口 URL、案件生成逻辑和问题次数规则。
- 不修改访问令牌、Cookie、Session 或登录逻辑。
- 不重构案件简报、正式审讯、结案报告和结果页面。
- 不修改 Caddy、Docker Compose、域名、环境变量或服务器配置。
- 不引入 3D 引擎、动画框架或重量级 UI 依赖。
- 不添加音效、背景音乐、粒子系统、鼠标跟随和高频故障动画。
- 不在本轮自动部署生产环境。

## 4. 当前实现与安全边界

### 4.1 当前首页

当前首页由以下部分组成：

- `LandingPage`：顶部导航、Hero 文案、产品预览和三步流程。
- `StartCaseButton`：调用动态案件生成接口，创建 Session 并进入简报；失败时提供固定案回退。
- `AccessMenu`：退出访问会话。
- `globals.css`：全局 Token、首页、访问页和游戏页面样式。

### 4.2 现有启动数据流

```text
点击首页 CTA
  → gameApi.generateCase()
  → 轮询案件生成任务
  → gameApi.createSession(caseId)
  → 保存 sessionId
  → router.push(案件简报 URL)
```

动态案件生成失败时：

```text
显示错误
  → 用户点击「改用精修固定案继续体验」
  → gameApi.getFallbackCase()
  → gameApi.createSession("001")
  → 进入 CASE-001 简报
```

该数据流、错误处理和路由行为必须保留。首页动画只消费现有的加载阶段和请求结果，不改变业务含义。

### 4.3 工作树状态

当前线上对应 `feature/llm-case-generation` 工作树。该工作树已有与动态案件、鉴权和部署有关的未提交改动。开发过程中必须保留这些改动，不得清理、覆盖或混入首页无关重构。

## 5. 页面结构

新版首页为单屏、无滚动的案件启动场景，只保留：

- 左上角的小型「AI 审讯室」标识。
- 右上角弱化后的现有退出入口。
- 占据首屏主体的审讯场景。
- 一句产品说明。
- 一个「生成案件」按钮。

删除当前首页中的以下内容：

- `CASE SYSTEM / 12+`
- `INTERROGATION READY`
- CASE-001 产品预览
- Evidence 卡片
- 工作台式聊天预览
- 三步流程说明
- 免费、免注册、首案开放和时长等营销文案
- 页面下方的补充机制区

## 6. 人物与构图

### 6.1 总体镜头

采用半写实电影海报式剪影。光源、站立者和 AI 嫌疑人在空间中保持同轴关系，镜头向侧面偏约 10–15°，避免站立者完全遮挡嫌疑人。

```text
后方光源 ───── 站立审讯者 ───── 坐着的 AI 嫌疑人
                                  ╲
                                   ╲ 镜头
```

场景采用克制的近对称构图，站立者负责建立空间和权力关系，坐着的 AI 嫌疑人始终是最终视觉焦点。

### 6.2 站立审讯者

- 代表玩家本人，位于前景。
- 采用偏过肩的背影，只显示后脑、肩膀、部分背部和一只自然垂下的手。
- 身体约占桌面画面高度的 70%，因透视关系比嫌疑人大约大 1.6–1.8 倍。
- 头部轻微低俯，肩线稳定，姿态克制。
- 穿无徽章、无身份标识的深色结构化外套。
- 不露脸，不穿警服，不戴礼帽，不携带武器，不做威胁动作。
- 轮廓语言为高、直、稳定、完整。

### 6.3 AI 嫌疑人

- 位于画面中央偏下，坐在结构简单的金属凳上。
- 采用偏瘦、性别模糊的人类轮廓，避免与动态生成案件中的具体人物身份冲突。
- 双脚自然落地，身体略微前倾，双手放在膝盖之间或分别搭在大腿上。
- 头部轻微低下，肩膀内收，表达戒备而非认罪。
- 穿无身份特征的深灰上衣和长裤，不穿囚服，不戴手铐。
- 整体约 80% 为人类剪影，约 20% 为数字重构痕迹。
- 数字痕迹集中在头部、颈部和一侧肩膀：一侧轮廓完整，另一侧逐渐断裂为网格、颗粒和不连续面片。
- 局部边缘可发生非常轻微的横向错位，影子可比身体慢半拍。
- 不使用机械眼、金属骨骼、蓝色发光芯片和明显机器人结构。
- 轮廓语言为低、收缩、不稳定、不完整。

## 7. 点击前灯光

点击前使用偏冷、低饱和的灰白后方光：

- 光源位于站立者后方偏高位置。
- 光束穿过少量空气颗粒，形成可见但克制的体积光。
- 站立者挡住部分光线并形成完整黑色剪影。
- 阴影沿地面延伸到 AI 嫌疑人身上。
- 嫌疑人的半张脸、胸口和一侧身体位于站立者投下的阴影中。
- 另一侧只由微弱余光勾勒出金属凳和 AI 边缘。
- 初始状态不能看清嫌疑人身份，但也不能让人物完全消失。

## 8. 首页文案与艺术字

首页只保留一句产品说明：

> 用 8 次提问，审讯一个会撒谎、却无法改写真相的 AI 嫌疑人。

桌面端可以分行排版，但仍保持一个完整句子。

- 普通部分使用暖白色。
- 「会撒谎」与「AI 嫌疑人」使用同一组暖白、暗红和冷灰流光，完整周期约 6–8 秒。
- 「无法改写真相」固定为低饱和警戒黄，不参与变色。
- 颜色变化采用字面内部的缓慢光带，不使用彩虹渐变或蓝紫渐变。
- 点击后艺术字停止流动并淡出。
- `prefers-reduced-motion: reduce` 下所有文字保持静态。

主按钮文案为「生成案件」。正常状态下不显示其他辅助说明。

## 9. 4 秒案件启动动画

案件生成请求在点击瞬间发出，动画与网络请求并行。动画不能延迟 API 调用；若请求异常快速完成，也应至少完成启动仪式后再导航，避免画面被截断。

| 时间 | 动作 | 目的 |
| --- | --- | --- |
| 0–0.25 秒 | 按钮立即响应，艺术字和按钮开始淡出 | 确认点击成功 |
| 0.25–1.25 秒 | 后方灰白光分 3 次不规则衰减并熄灭 | 关闭原有空间 |
| 1.25–1.55 秒 | 保留约 0.3 秒近黑场 | 建立停顿和预期 |
| 1.55–2.75 秒 | 机械封存框架从上方落下 | 展示封锁过程 |
| 2.75–3.15 秒 | 框架轻微机械回弹，锁扣闭合 | 确认空间已封锁 |
| 3.15–3.65 秒 | 约 3000K 的暖白钨丝顶灯由暗到亮 | 重新建立视觉焦点 |
| 3.65–4.0 秒 | AI 嫌疑人的轮廓和数字痕迹显现 | 审讯对象正式出现 |

闪烁必须是低频的光强衰减，不得形成高频频闪。减少动态效果模式下，改为后方光淡出、框架直接出现和顶灯淡入，总时长缩短但保留完整状态语义。

## 10. 生成中的稳定状态

4 秒启动动画结束后，页面进入稳定生成状态：

- 封存框架保持闭合。
- 暖白顶灯稳定照射嫌疑人的头部、上半身和金属凳。
- 顶灯中心接近象牙暖白，边缘过渡到低饱和琥珀色。
- 后方光保持熄灭。站立者只接收顶灯溢出的微弱轮廓光，不重新点亮原始光束。
- AI 嫌疑人的数字边缘继续缓慢构建，但不重复大幅动画。
- 页面底部一次只显示一条真实生成状态：
  - 「正在生成案件」
  - 「正在核验证据链」
  - 「正在封存真相」
- 不展示虚假百分比，不展示参数、日志、证据卡或技术术语。

## 11. 完成与失败

### 11.1 生成成功

- AI 人物停止变化。
- 锁扣转为低饱和警戒黄。
- 显示 `TRUTH LOCKED / 真相已封存`。
- 停留约 0.5 秒后进入现有案件简报页面。
- Session 的创建、保存和路由地址保持现有逻辑。

### 11.2 生成失败

- 不进入简报页面。
- 封存动画停止，页面保持可读。
- 显示现有业务错误信息。
- 保留「改用精修固定案继续体验」入口。
- 固定案回退继续调用现有 API，不在首页伪造 CASE-001 数据。

## 12. 视觉系统

- 背景：暖黑和深石墨灰，不使用纯黑。
- 主文字：暖白。
- 动态欺骗色：暗红、冷灰和暖白。
- 固定真相色：低饱和警戒黄。
- 顶灯：约 3000K 的暖白钨丝灯质感，不使用大面积黄色钠灯。
- 框架：暗色机械金属，边缘只保留少量反光。
- 不使用蓝紫 AI 渐变、大面积霓虹、浓雾和高亮网格背景。

## 13. 响应式

必须检查 1440、1280、1024、768 和 390 px 宽度。

### 13.1 桌面端

- 站立者保留过肩背影和明显的前后景比例。
- 嫌疑人位于视觉中心，封存框架完整可见。
- 艺术字和按钮位于不遮挡人物、光束和阴影的安全区域。

### 13.2 平板与移动端

- 不是等比例缩小桌面构图。
- 站立者只保留肩部和部分背影，减少遮挡。
- AI 嫌疑人位于上半屏中心。
- 产品说明和按钮位于下半屏安全区域。
- 封存框架改为更明显的纵向闭合关系。
- 页面保持单屏，无横向滚动，按钮满足 44 px 最小触控尺寸。

## 14. 无障碍与性能

- 保留清晰的键盘焦点和按钮语义。
- 加载状态使用 `role="status"`，错误状态使用 `role="alert"`。
- 禁止可能诱发不适的高频闪烁。
- `prefers-reduced-motion` 下关闭文字流光、频闪和机械回弹，改用短淡入淡出。
- 场景优先使用分层 SVG、CSS 和现有 React 能力，不新增动画框架。
- 动画只作用于 `transform`、`opacity`、遮罩和有限的颜色属性，避免持续触发布局计算。
- 资源需要兼顾桌面与移动裁切，并避免阻塞首屏交互。

## 16. 验收标准

### 16.1 功能

- 未点击前只发出必要请求，不提前创建案件。
- 点击「生成案件」后只触发 1 次生成流程。
- 加载期间按钮不可重复触发。
- 生成成功后创建 Session 并进入正确的动态案件简报。
- 生成失败时能进入现有固定案回退流程。
- 登录过期、网络失败和超时行为保持现有逻辑。

### 16.2 视觉与交互

- 首页为单屏，无后台式预览和长内容区。
- 点击前能看清站立者遮挡后方光线、嫌疑人部分处于阴影中的关系。
- AI 嫌疑人首先是人类轮廓，其次才显露数字重构特征。
- 4 秒启动动画按熄灯、黑场、落笼、锁定、顶灯亮起的顺序执行。
- 生成期间没有重复落笼、虚假进度和高频闪烁。
- 艺术字只在「会撒谎」与「AI 嫌疑人」部分流动，「无法改写真相」保持固定警戒黄。
- 减少动态效果模式可完整使用。
- 5 个目标宽度均无横向溢出和关键内容遮挡。

### 16.3 工程质量

- 不新增依赖。
- 现有单元测试通过。
- `npm run typecheck` 通过。
- `npm run lint` 通过。
- `npm run build` 通过。
- 本地端到端流程通过。

## 17. 上线与回滚

1. 基于当前线上对应代码建立独立首页改版分支，并保留现有未提交改动。
2. 本地完成实现、测试和目标尺寸截图。
3. 交付本地预览，由用户人工确认。
4. 未获得明确部署授权前不修改生产环境。
5. 获得授权后只构建和替换前端 Web 容器；API、数据库、Caddy、域名和环境变量不动。
6. 上线后验证访问登录、首页动画、动态案件生成、固定案回退、简报跳转和移动端。
7. 保留旧前端镜像或构建产物；发生异常时直接恢复旧 Web 容器。
