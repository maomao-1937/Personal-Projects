# AI 审讯室访问令牌与上线设计

## 一、目标与范围

本轮把已经验收的 AI 审讯室升级为可受控访问的线上产品，并部署到火山引擎 veFaaS。

交付范围：

- 只发行 1 个共享访问令牌；
- 访问令牌换取安全登录会话，不在后续请求中反复传输明文令牌；
- 所有案件、审讯、结案和结果接口必须鉴权；
- 清除线上界面中的版本号、Demo、MVP、测试态和开发态表达；
- 前后端分别部署为 veFaaS Application，复用现有 Serverless API 网关；
- 后端保持至少 1 个预留实例，并备份 SQLite 数据；
- 上线后完成真实令牌、真实模型和完整游戏链路验收。

不在本轮实现账号注册、找回密码、多人房、支付、排行榜或管理后台。

## 二、访问令牌方案

### 2.1 登录方式

采用「访问令牌换登录会话」：

1. 用户访问产品，未登录时进入访问验证页；
2. 用户输入唯一访问令牌；
3. 前端通过 HTTPS 将令牌提交到后端；
4. 后端使用恒定时间比较校验令牌哈希；
5. 校验成功后签发带签名的会话 Cookie；
6. 后续请求只携带 Cookie，不再携带明文访问令牌。

访问令牌由上线流程随机生成，只在最终交付时明文提供给产品负责人。代码仓库、前端构建产物、日志和数据库均不保存明文令牌。

### 2.2 Cookie 与会话

- Cookie 属性：`HttpOnly`、`Secure`、`SameSite=Lax`、`Path=/`；
- 有效期：7 天；
- 内容：匿名访问主体 ID、签发时间和过期时间；
- 签名：服务端 `AUTH_SIGNING_SECRET` 生成 HMAC；
- 退出登录时服务端清除 Cookie；
- Cookie 缺失、过期或签名错误统一返回 `401 AUTH_REQUIRED`。

### 2.3 防滥用

- 错误令牌统一返回 `401 INVALID_ACCESS_TOKEN`，不暴露校验细节；
- 同一来源连续失败达到阈值后，短时间返回 `429 AUTH_RATE_LIMITED`；
- 日志只记录追踪号、结果和耗时，不记录令牌、Cookie 或用户输入；
- 健康检查保持公开，其余 `/api/v1` 业务接口默认受保护。

## 三、数据归属与隔离

唯一访问令牌对应一个匿名访问主体。创建 Session 时写入主体 ID；读取 Session、提交回合和结案报告时均校验主体归属。

即使 Session ID 被他人获得，只要登录主体不匹配，后端也返回 `403 SESSION_FORBIDDEN`。案件公开简报在登录后可读取，完整真相仍只在完成结案后通过现有评分结果返回。

数据库迁移新增 Session 所有者字段，旧本地数据使用受控兼容值，不自动暴露给线上访问主体。

## 四、页面与产品文案

新增访问验证页，沿用现有审讯工作台设计语言：黑色工作台、灰米白文件卡、细边框、低圆角、无霓虹和无大阴影。

页面只展示：

- 产品名「AI 审讯室」；
- 一句访问说明；
- 访问令牌输入框；
- 「进入审讯室」按钮；
- 安全且可恢复的错误提示。

上线前扫描所有用户可见页面、HTML Metadata 和错误文案，移除以下表达：

- Demo、MVP、测试版、内测版；
- v0、v1 或其他产品版本号；
- 「测试案件」「假数据」「开发环境」等实现信息；
- 暴露模型名称、Provider、数据库或部署平台的技术文案。

技术文档和代码内部的迁移版本不属于用户界面，不做无意义删除。

## 五、前后端边界

后端新增：

- `POST /api/v1/auth/login`：访问令牌换 Cookie；
- `GET /api/v1/auth/session`：确认当前登录状态；
- `POST /api/v1/auth/logout`：清除 Cookie；
- 鉴权中间件或依赖：保护业务接口；
- Session 所有者校验；
- 结构化 `trace_id` 响应头和日志。

前端新增：

- `/access` 访问验证页；
- 未登录业务页自动进入 `/access`；
- API 收到 `401` 时清理本地游戏 Session 并进入验证页；
- 登录成功后返回原目标页或落地页；
- 不使用 `localStorage` 保存访问令牌。

Next.js 继续通过同源 `/api/v1` 代理后端，浏览器不直接访问后端域名。

## 六、数据持久化与部署

部署采用两个 veFaaS Application：

- 后端：FastAPI，端口 8000；
- 前端：Next.js Standalone，端口 3000；
- 两者复用现有 Serverless API 网关；
- 前端构建时注入后端公网地址；
- 所有秘密通过 veFaaS Secret / 环境变量配置。

后端数据库使用 `/tmp/data/ai-interrogation.db`。后端设置 1 个预留实例，并将数据库定期备份到 TOS；启动时本地库缺失则从最近备份恢复。产品没有用户上传文件，因此本轮不增加业务文件存储。

上线环境变量至少包括：

- `APP_ENV=production`；
- `DATABASE_URL=sqlite:////tmp/data/ai-interrogation.db`；
- `LLM_ENABLED=true`；
- 模型服务地址、模型名和服务端 API Key；
- `ACCESS_TOKEN_HASH`；
- `AUTH_SIGNING_SECRET`；
- TOS 备份配置；
- 前后端允许来源配置。

`.env`、`.venv`、`data`、缓存、测试产物和 `.vefaas` 配置不得进入部署包。

## 七、错误与恢复

- 登录错误保留输入焦点，但清空令牌值；
- 网络中断显示可重试提示，不展示堆栈；
- Cookie 过期后统一回到访问验证页；
- 模型生成失败仍允许用户显式进入精修固定案；
- 数据备份失败记录结构化错误，不阻塞正在进行的审讯；
- 部署失败保留上一个可用版本，不删除现有云资源。

## 八、测试与验收

自动化测试：

- 正确令牌登录成功并设置安全 Cookie；
- 错误令牌、缺失令牌、过期 Cookie 和篡改 Cookie 被拒；
- 连续错误登录触发限频；
- 未登录不能访问案件、Session、回合和报告接口；
- 登录主体不能访问其他主体的 Session；
- 前端登录成功、错误提示、401 跳转和退出登录；
- 线上 HTML 不包含 Demo、MVP、版本号和测试态文案。

上线验收：

1. 公网 HTTPS 地址可打开；
2. 无 Cookie 自动进入访问验证页；
3. 错误令牌被拒，正确令牌可进入；
4. 生成动态案件并完成至少 1 次有效证据命中；
5. 完成结案、查看真相并生成下一案；
6. 手机与桌面视口无横向滚动；
7. 刷新后登录状态和当前游戏可恢复；
8. 后端日志不出现访问令牌和模型 API Key；
9. 数据库备份存在，并验证恢复流程；
10. 最终只向产品负责人交付产品名、访问令牌和前端网页地址。

## 九、上线限制

本地规则型内容审核适合当前受控主题和小范围访问。扩大公开流量前，需要接入独立内容审核服务、网关限流、集中错误告警和更稳定的数据库。当前上线以单访问主体、小规模体验为边界，不宣称支持公开大并发。
