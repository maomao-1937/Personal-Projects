# AI 审讯室｜大模型案件生成与嫌疑人表演设计

日期：2026-08-25  
状态：已完成设计，待用户书面规格复核

## 1. 目标与边界

本阶段把当前单一 `CASE-001` 确定性 Demo 升级为可连续开局的 AI 案件系统。玩家点击开始时建立一份新的不可变案件实例，结案后可选择重玩同案或生成下一案。

大模型只负责两类内容能力：生成案件草案、组织嫌疑人的临场回答。固定真相、证据命中、心理状态、证据解锁、回合限制、结案门槛和评分继续由后端结构化规则决定。

不在本阶段实现账号、支付、多人、语音、地图探索、案件编辑器、完整异步任务队列和云端案件池调度。

## 2. 方案比较与选择

### 方案 A：每次点击都完全实时生成

新鲜感最高，但生成耗时、模型故障和成本会直接阻塞开局，不适合作为唯一生产路径。

### 方案 B：只从预生成案件池领取

开局最快、稳定性最好，但当前阶段需要额外的后台生产与库存系统，也削弱用户对“正在生成新案件”的感知。

### 方案 C：实时生成 + 固定案降级 + 后续案件池（采用）

本阶段优先实时生成并做严格校验；没有密钥、模型超时或多次校验失败时，明确提示并允许使用固定案件继续体验。上线阶段再加入预生成案件池，优先秒开库存并在后台补充。该方案已由用户在对话中确认。

## 3. 核心用户流程

```text
落地页点击“生成免费案件”
→ 展示“建立案卷 / 锁定真相 / 校验证据链”进度
→ POST /api/v1/cases/generate
→ 后端生成、程序校验并冻结案件实例
→ 创建该案件的 Session
→ 动态案件简报
→ 8 回合内审讯
→ 主动提交结构化报告
→ 完整真相复盘
→ “重新审讯同案”或“生成下一案”
```

生成失败时保留当前页面，提供“重新生成”和“使用固定案件”两个动作。不能把降级案件伪装成刚生成的新案件。

## 4. 案件实例模型

新增 `cases` 表，保存服务端私有的完整案件快照：

- `id`：不可猜测的案件实例 ID，例如 `case_<uuid>`；
- `case_code`：用户可见短编号；
- `schema_version`：案件结构版本；
- `source`：`llm` 或 `manual_fallback`；
- `model_name`：生成模型标识，不保存密钥；
- `content_json`：完整私有案件 JSON；
- `created_at`、`expires_at`、`status`；
- 创建后不可修改，Session 始终绑定该快照。

案件 JSON 必须包含：

- 标题、时间、地点、概要、12+ 分级；
- 嫌疑人公开资料、隐藏软肋和行为风格；
- 初始证词、公开事实；
- 恰好 5 条证据，其中恰好 2 条公开；
- 恰好 3 个谎言节点；
- 每个谎言节点对应证据、确定性主题关键词、防线变化、证据解锁和局部承认；
- 3 个真相选项、3 个动机选项、3 个手法选项，且各自只有一个正确 ID；
- 5–7 个时间线节点；
- 核心证据权重总和不超过 20；
- 有效命中、重复、无关证据、施压、共情、普通追问和最终承认的降级回答模板。

公开案件接口必须删除完整真相、隐藏软肋、谎言节点、答案 ID、权重、内部关键词和回答模板。

## 5. 生成与校验

服务端通过 OpenAI-compatible `/chat/completions` 适配层调用模型。配置只来自服务端环境变量：

```text
LLM_API_KEY
LLM_BASE_URL
LLM_MODEL
LLM_TIMEOUT_SECONDS
LLM_ENABLED
```

生成器要求模型返回 JSON，不接受自由文本。校验分两层：

1. Pydantic 与程序校验：字段、数量、唯一 ID、引用完整性、唯一正确答案、证据覆盖、时间线、分值和内容长度；
2. 自洽复核：使用第二次模型调用只返回问题列表与 `pass/fail`，检查时间矛盾、答案不唯一、证据无法推出真相和不适合 12+ 的内容。

程序校验失败或复核失败最多重新生成 2 次。全部失败后返回可恢复错误，不保存半成品案件。测试通过依赖注入的 Fake Provider，不调用真实模型。

## 6. 审讯回答数据流

规则引擎先对玩家输入做确定性判断，再允许模型表演：

```text
玩家问题 + 策略 + 证据 ID
→ 规则引擎计算 topics、命中节点、证据作用、防线变化和解锁项
→ 形成 ReplyDirective
→ 模型根据嫌疑人人格、已公开事实、已发生对话和本回合允许透露内容生成 2–4 句回答
→ 回答通过长度、泄密和空内容检查
→ 保存 Session 与回答
```

`ReplyDirective` 明确提供 `intent`、`allowed_facts`、`must_acknowledge`、`forbidden_facts` 和心理状态。模型不能修改规则结果，也不能决定是否认罪。模型失败时使用案件快照内的降级模板，确保回合不丢失。

为保持回合幂等，同一个 `requestId` 必须返回第一次持久化的完整结果，重试不能再次调用模型或消耗回合。

## 7. API 契约

新增或调整：

- `POST /api/v1/cases/generate`：生成并冻结案件，返回公开案件和 `generationSource`；
- `GET /api/v1/cases/{case_id}`：读取任意公开案件实例；保留 `001` 读取手工案；
- `POST /api/v1/sessions`：使用请求中的动态 `caseId` 创建 Session；
- Session、Turn、Report 响应继续携带 `caseId`；
- Turn 接口契约不改变，但服务内部增加回答 Provider；
- 健康检查增加不泄露密钥的 `llmConfigured` 与 Provider 状态。

生成接口采用同步请求，本阶段前端超时设置为 90 秒。上线阶段若平台请求上限不允许，再将同一服务边界替换为任务 ID + 轮询，不改变案件模型和前端状态语义。

## 8. 前端与路由

静态 `/case/001/*` 升级为：

```text
/case/[caseId]/briefing
/case/[caseId]/interrogate
/case/[caseId]/report
/case/[caseId]/result
```

Session ID 仍放在查询参数中，案件 ID 由路径提供；恢复时必须验证两者匹配。

落地页 CTA 改为“生成免费案件”。生成期间使用现有 Factory 视觉语言显示三个机械步骤，不伪造百分比。按钮禁用并通过 `aria-live="polite"` 宣告状态。

结果页提供两个清晰动作：

- “重新审讯同案”：只创建绑定当前案件的新 Session；
- “生成下一案”：重新调用生成接口，成功后进入新案件简报。

若没有模型密钥，生成动作显示“当前未配置生成模型”，并允许用户显式选择固定案件，不自动假装生成成功。

## 9. 错误、安全与成本控制

- API Key 只存在后端环境变量，不进入前端包、数据库、日志或错误响应；
- 模型请求记录耗时、状态和匿名 request ID，不记录完整秘密 Prompt；
- 对模型输出做 12+ 内容约束和危险内容拒绝；
- 对外只返回安全错误文案；
- 生成请求、模型回答均设置超时；回答失败降级，案件生成失败不落库；
- 正式公网发布前在网关增加生成限流、单 IP 配额和案件 TTL 清理；
- 当前 SQLite 仅用于本地核验，公网多用户版本迁移 PostgreSQL。

## 10. 测试与验收

后端先写失败测试并验证红灯，再实现：

- 合法生成结果可保存并通过公开投影读取；
- 错误数量、悬空引用、重复 ID、多个正确答案和超限分值均被拒绝；
- 模型超时、非法 JSON、自洽复核失败触发重试，最终失败不落库；
- 无密钥返回明确状态，固定案降级必须由客户端显式请求；
- 动态案件可创建 Session、完成证据命中和结构化评分；
- 回答模型失败时使用模板，规则结果不变；
- 相同 Turn `requestId` 不重复调用模型；
- 私有真相和软肋不进入公开 API。

前端验收：

- 生成进度、错误、重试和固定案降级均可键盘操作；
- 动态案件四个路由可刷新恢复；
- 结案后“重新审讯同案”和“生成下一案”行为不同；
- 360 px 无横向滚动；
- 无 Key 时仍能显式进入固定案完成一局；
- lint、typecheck、单元测试、build、完整 E2E 和四视口检查全部通过。

## 11. 成功标准

配置有效 API Key 后，连续点击“生成下一案”得到不同的不可变案件实例；每案保持固定真相和自洽证据链。审讯语言由模型自然生成，但同样的结构化行为仍由规则引擎判定，失败与重试不会重复扣回合。没有 Key 或模型故障时，用户能理解当前状态并显式使用固定案件完成体验。
