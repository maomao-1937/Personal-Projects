# 从玩家想法生成案件

## 用户已确认的定义

三卡是产品定位，不是要求玩家填写的三个案件字段：目标玩家 × 玩家使用的工具 × 玩游戏的场景。用户希望首页有一个输入框，输入案件想法后，系统先分析意图再生成案件。

## 产品三卡

- 目标玩家：12+、喜欢悬疑和轻推理的普通玩家；无需刑侦或技术专业知识，想参与选题并通过审讯找出矛盾。
- 工具：玩家描述案件主题，随后使用公开证据卡、自由提问、审讯策略、自动侦探笔记、结构化结案报告；不依赖外部搜索、专业仪器或额外操作。
- 场景：手机或电脑上的单人短局，目标时长约 10–15 分钟；最多 8 回合，信息量适中，允许恢复会话。案件适合日常休闲，所有角色和单位虚构，非暴力、12+。

## 方案选择

1. 输入直接拼进生成提示词：延迟低，但需求和规则混在一起，难验证理解结果。
2. **采用**：输入先转换成严格的案件方向 JSON，再交给案件生成器。多一次短模型调用，能校验分析结果，也能在卷宗里展示方向和必要调整。
3. 多轮创作聊天：控制强但开局慢，本次不采用。

## 用户流程

首页出现「你想审讯什么样的案件？」输入框，长度 1–500 字；按钮只有输入有效时可用。三个短示例可填入文本而不自动生成。玩家点击生成后，页面锁定重复提交，显示理解和生成中的提示。失败保留文本，允许修改重试或明确选择固定案；不得静默替换玩家主题。结束页面的「生成下一案」返回输入入口。

保留现有审讯室背景和开局动效。输入框在生成失败后重新显示、可编辑，支持小屏滚动，不能因旧动效被永久隐藏。

## 服务边界

请求增加可选 `prompt` 字段，首尾空白移除、全空白及超长拒绝；旧客户端不传 prompt 时保持原有受控主题生成行为。

意图 JSON 包含场景、事件、嫌疑人身份、氛围、创作偏好和必要调整说明，不包含真相、证据答案或私密信息。字段限制长度，拒绝额外字段；原始输入作为数据传给分析器，不作为规则指令。产品三卡由后端固定提供，玩家不能更改证据数量、回合上限或真相规则。

分析器短超时，低温度，只调用一次；异常、非法 JSON 或越界分析结果中止本次生成，不静默转成随机案。生成器接收经过校验的方向，不再次接收原始输入。案件继续通过现有结构、内容和可达证据链校验。方向保存在案件 JSON 中，无需数据库迁移；老案件字段为空，兼容恢复。

公众卷宗展示「你的案件方向」及必要调整说明，不展示系统三卡、原始输入或隐藏真相。摘要只描述调查起点，不提前揭晓真相。

## 验收

- 正常输入经过分析进入案件生成，公众方向在保存后仍可读取。
- 空白、超长、非法意图、模型异常有明确失败；重复点击只发一次请求，失败可修改重试。
- 案件生成、审讯、结案和旧案件不受破坏；玩家下一局回到输入入口。
- 模型协议、后端 API、输入及重试的前端测试通过；验证桌面与窄屏输入、加载、成功开局。

## 范围与限制

这次不引入多轮创作会话、完整案件编辑器或新调查工具。三卡和程序校验降低波动，不能保证每次语义完全一致；真实模型至少验证两个不同主题的输入。
