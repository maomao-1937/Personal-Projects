# 技术适配声明

## 1. 产品形态判断

- 产品类型与核心任务：C 端网页推理游戏；玩家在最多 8 回合内盘问一名会隐瞒事实的嫌疑人，并主动提交结构化结案报告。
- 核心交互：多轮对话 + 证据选择 + 分阶段确认；没有动态工具调用。
- 开发路径：后端先行，再完成一条正式 Web 纵向闭环。原因是案件真相、谎言命中和评分必须先通过独立 API 验证，而审讯体验随后直接接入这套契约。
- 当前阶段范围：1 个手工案件、确定性规则引擎、匿名 Session、五个正式页面、本地可试玩闭环。

## 2. 采用的默认方案

- Python 3.11.15 + FastAPI：实现可独立验证的案件、回合、Session 与评分 API。
- Pydantic：约束所有请求、响应和案件数据。
- pytest：覆盖规则、状态流转、输入校验、幂等与 API 错误路径。
- SQLAlchemy + SQLite：Session 需要跨刷新和后端重启恢复；数据库地址由环境变量控制，后续可迁移到 PostgreSQL。
- Next.js App Router + TypeScript strict + Tailwind CSS：实现唯一正式终端——响应式 Web。
- Vitest + React Testing Library + Python Playwright：覆盖前端纯函数、组件状态与完整用户闭环。
- npm：当前 Node.js 24.18.0 可用，项目固定实际依赖到锁文件。
- API 前缀：统一使用 `/api/v1`。

## 3. 触发的按需模块

- SQLAlchemy：Session 与报告需要事务、幂等提交和持久化，当前阶段引入。
- Alembic：关系型数据结构需要可追踪迁移，当前提供 Session、并发 revision 与回合幂等请求三步迁移；生产采用独立迁移步骤。
- Lucide React：提供一致、轻量的界面图标。
- 不引入：真实 LLM SDK、SSE、RAG、任务队列、对象存储、登录、支付、语音、全局状态库、完整 UI 框架。

## 4. 偏离或暂缓的默认方案

- PRD 曾建议 Next.js Route Handlers；本阶段改用独立 FastAPI。原因是用户明确要求按通用后端手册先完成并核验后端，也便于后续 veFaaS 分离部署。影响是本地需启动两个进程；前端通过同源代理消除 CORS。
- 当前不调用 LLM，使用案件内预设回答模板。原因是本轮验收要求确定性 Demo。未来接入模型时，仅替换回答表演服务，不改规则引擎和评分契约。
- 回合请求携带客户端生成的 `requestId`，持久化响应后允许安全重试；Session 更新同时使用 revision 条件写，防止并发丢失更新。
- 当前 SQLite 存在本地 `data/`。上线时迁到 `/tmp/data/`，并按部署手册增加预留实例、对象存储备份和启动恢复；本轮不提前创建付费云资源。
- 不实现登录和用户隔离。原因是本轮明确为免注册本地 Demo；正式公开上线前必须补齐。

## 5. 强制底线检查

- 密钥与隐私：通过；当前不需要 Key，仓库只保留无秘密的 `.env.example`，后续模型 Key 仅由后端读取。
- 数据与任务可恢复：通过设计；Session 与报告持久化到 SQLite，不依赖进程内存。
- 输入输出校验：通过设计；Pydantic 校验问题长度、策略、证据与报告字段。
- 错误与日志边界：通过设计；API 统一返回安全错误，不向浏览器暴露堆栈。
- 测试与真实模型验收：当前无模型调用，因此只做确定性自动化与真实浏览器验收；真实模型冒烟明确留到用户提供 Key 后。

无。当前实现范围、视觉方向、案件数量、回合数和不调用真实 LLM 均已由用户明确。
