# MeetingMemo 前端 UI 设计规格

日期：2026-08-23  
状态：用户已授权按推荐方案直接实现并在成品阶段验收

## 1. 设计目标

MeetingMemo 是封闭 Beta 阶段的会议摘要工作台。界面应像一册安静、专业、可编辑的数字会议笔记，而不是营销网站或通用后台模板。主要任务是让用户快速完成：导入转录、等待 AI 处理、阅读来源、核对结论、修订摘要、审批并导出。

设计以项目根目录 `DESIGN.md` 为视觉基线，并采用 Granola 的纸张感、编辑感和橄榄绿色谱；不复制其营销官网布局、超大标题、装饰性渐变或社交证明组件。

## 2. 信息架构

### 2.1 邀请码入口

- 不出现注册、登录、找回密码和用户资料概念。
- 单一邀请码输入框和“进入 MeetingMemo”主操作。
- 说明邀请码可使用次数由服务端管理，前端不自行计数。
- 成功后依赖 HttpOnly Cookie；失败时显示后端返回的可行动中文错误。

### 2.2 主工作台

桌面端采用持久三栏：

1. 左栏：品牌、创建会议、会议列表、简洁导航及退出。
2. 中栏：会议标题与状态、摘要正文、转写原文、编辑模式。
3. 右栏：关键结论、决策事项、行动项、待确认问题和质量提示。

桌面结构建议为 `248px / minmax(520px, 1fr) / 340px`。页面不设置营销式最大宽度，主工作区使用视口空间；正文阅读列在中栏内部控制行长。

### 2.3 新建会议

- 在工作台内打开轻量抽屉或内嵌创建面板，不跳转到营销式向导。
- 先填写标题、会议时间、语言，再选择“粘贴转写”或上传 `.txt/.vtt/.srt`。
- 音频和视频入口可见但明确标记“转录服务待配置”，不可伪装为已支持。
- 创建与上传完成后启动摘要任务，并在会议列表和正文标题旁显示小型处理指示器。

## 3. 核心交互

### 3.1 阅读与溯源

- 摘要主题位于中栏，右栏结构化条目用于快速扫描。
- 每个 AI 条目使用浅橄榄标签或左侧细色条标记。
- 条目上的来源标记显示时间或片段序号；点击后切换到转写并滚动、聚焦对应片段。
- 转写片段按说话人、时间和正文排列，不使用聊天气泡。

### 3.2 编辑与版本

- “编辑摘要”进入结构化编辑态；标题、主题、决策、行动项、负责人、截止时间和待确认问题均可修改。
- 保存时提交完整结构化内容和 `expected_version`，由后端创建新修订版。
- 遇到版本冲突时保留用户输入，提示刷新最新版本后再合并，绝不静默覆盖。
- 最新版本可审批；已经审批的版本显示小型状态标签。

### 3.3 导出与分发

- 导出菜单支持 Markdown、纯文本和 JSON，直接使用后端下载接口。
- Slack/Email 只有服务端返回 `configured` 时可操作；未配置时显示简短原因。
- 分发结果区分成功、失败和未知，不用纯颜色表达。

### 3.4 任务状态

- 状态为排队、处理中、完成、失败。
- 处理中仅使用 8px 状态点与短文案，不使用大型动画。
- 前端轮询任务，页面不可见时降低或暂停轮询，终态立即停止。
- 失败态保留会议和转写，提供重试；缺少模型密钥时给出明确配置提示。

## 4. 视觉系统

### 4.1 颜色

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 纸张画布 | `#f7f7f2` | 页面背景 |
| 白色表面 | `#ffffff` | 卡片、输入、栏面 |
| 墨色 | `#0e0f0c` | 标题与正文 |
| 次级文字 | `#72726e` | 元信息、辅助文案 |
| 细边框 | `#e3e3e3` / `#d5d5d2` | 分栏、卡片和控件 |
| 主操作 | `#5b6f00` | 唯一的深橄榄填充按钮 |
| AI 浅底 | `#e5eacd` | AI 标签和内容提示 |
| AI 边线 | `#788c15` | 焦点与 AI 标记 |
| 录制/严重错误 | `#e95d3d` | 小型状态点及错误点缀 |

主操作色不用于大面积背景。卡片默认无阴影，以 0.5–1px 边框区分。

### 4.2 字体与字号

- 标题：Lora，常规字重；页面标题 28–32px，区块标题 20–24px。
- 正文与 UI：DM Sans；正文 15–16px，标签和元信息 12–14px。
- 中文环境依次回退到 `Noto Serif SC` / `Noto Sans SC` / 系统字体。
- 长文本行高 1.65–1.75，控件行高保持紧凑。

### 4.3 形状与间距

- 4px 基础节奏，常用间距 8/12/16/24/32px。
- 卡片和输入框 8px 圆角；标签与紧凑按钮可用胶囊圆角。
- 三栏之间使用细边框，不使用浮层阴影营造结构。
- 焦点态采用可见的橄榄色轮廓，不能只依赖颜色变化。

## 5. 响应式行为

- `>= 1180px`：完整三栏，左右栏独立滚动，中栏为主要阅读区。
- `768–1179px`：左栏保留，右栏改为可打开的洞察抽屉；正文占其余空间。
- `< 768px`：左侧会议列表和右侧洞察均为抽屉；中栏用“摘要 / 转写”标签切换；底部或标题栏保留创建、洞察和导出入口。
- 在 390、768、1280、1440px 宽度进行真实浏览器核验。

## 6. 页面状态

每个数据区必须覆盖：初始、加载、成功、空、失败、未授权和部分功能未配置。特别包括：

- 未兑换邀请码；邀请码错误或次数耗尽。
- 无会议时的导入引导。
- 已有会议但没有转写。
- 摘要排队、处理、失败、完成。
- 没有决策/行动项时的克制空态。
- Slack/Email/ASR 未配置。
- 版本冲突、审批失败和导出失败。

## 7. 无障碍与体验标准

- 所有按钮、表单和标签具备可读名称与键盘操作。
- 抽屉和对话框管理焦点，支持 Escape 关闭。
- 状态点必须配文字；错误提示用 `role=alert` 或合适的实时区域。
- 正文宽度、字距和行高优先服务长文本阅读。
- 尊重 `prefers-reduced-motion`，仅保留必要的短过渡。

## 8. 实现边界

- 前端不保存或展示任何服务端密钥。
- 前端不实现注册、登录或自行生成邀请码。
- 后端是会议、任务、摘要版本和集成状态的唯一事实源。
- 当前真实支持粘贴文本及 TXT/VTT/SRT；音视频待 ASR 服务配置后再启用。
- 真实 LLM 未配置时，保留完整失败与重试体验；不在生产界面伪造 AI 结果。
