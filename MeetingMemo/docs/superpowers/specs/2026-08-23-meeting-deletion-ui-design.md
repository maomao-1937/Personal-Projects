# MeetingMemo 历史会议删除交互设计

> 日期：2026-08-23
>
> 状态：已按用户明确要求确认

## 目标

让用户能直接从左侧「最近会议」列表删除历史会议，并移除左侧无实际筛选能力的「处理中」入口及会议条目中的同名状态文案。

## 交互方案

- 每条会议记录右侧显示垃圾桶图标按钮，按钮的无障碍名称包含会议标题。
- 点击垃圾桶只触发删除，不切换当前会议；删除前显示一次包含会议标题的确认提示。
- 用户确认后调用现有 `DELETE /api/v1/meetings/{id}` 接口。请求期间禁用该会议的删除按钮。
- 删除成功后立即从列表移除该会议并清理对应任务状态。
- 若删除的是当前会议，自动打开剩余列表中的第一条会议；列表为空时展示现有空状态。
- 删除失败时保留会议和当前内容，并显示后端返回的错误信息。

## 视觉与范围

- 删除按钮沿用侧栏的克制视觉：默认低对比度，悬停或键盘聚焦时提高可见度，危险状态使用现有错误色。
- 桌面端和移动端使用同一入口，触控区域不小于现有侧栏按钮。
- 删除左侧「处理中」导航框，以及最近会议条目内的「处理中」文字和圆点。
- 主内容区的排队、生成、失败和重试反馈继续保留，避免用户失去必要的任务状态信息。

## 验证

- 组件测试覆盖删除当前会议、删除非当前会议、取消确认、失败恢复和「处理中」文案移除。
- 运行前端单元测试、ESLint、TypeScript 类型检查和生产构建。
- 使用真实本地后端执行浏览器删除流程，确认会议从列表消失且刷新后不会恢复。
