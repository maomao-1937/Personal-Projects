# 核心素材驱动的方案生成设计

## 目标

调整首页主文案，并将项目生成入口从自由文本改为素材星库单选。用户选择一条素材作为核心起点后，系统从整个星库自动寻找其他可组合素材，再生成新的方案假设。

## 首页文案

- 删除原标题“从旧素材库里发现你的 / 下一个周末项目”。
- 将“散落的念头、网页和问题存进来。”移动到原标题位置，作为新的一级标题。
- 新标题沿用现有一级标题的字号、字重、行高、字距和紫色渐变强调方式。
- 标题下方说明删除已经上移的重复句，只保留“系统不会随机拼接，而会寻找真实问题与可借用机制，推进成一个有来源、可验证的方案假设。”

## 核心素材选择器

- 将“这次想探索什么？”文字输入框替换为“选择一条核心素材”单选控件。
- 点击控件后，在当前位置向下展开素材列表，不打开新弹窗。
- 列表只展示处理状态为 `ready` 的素材。
- 每条选项展示素材类型、标题和简短摘要。
- 用户每次只能选择一条素材；再次点击其他素材会替换当前选择。
- 选中后，选择框显示素材标题，并显示提示：“以此为核心，自动关联整个素材星库”。
- 点击选择器外部或按 Escape 关闭列表；键盘可以聚焦和选择选项。

## 生成流程

1. 用户从下拉列表选择一条核心素材。
2. 前端向 `/incubations` 发送 `seed_material_id`、可用时间和预算，不再发送用户自由输入的项目方向。
3. 后端验证核心素材属于当前用户且处理状态为 `ready`。
4. 检索器保证核心素材进入候选集，并从其余可用素材中优先选择内容相关的素材；相关度相同时使用稳定顺序。
5. 如果关键词相关素材不足，仍从其余可用素材中补齐候选集，让 AI 判断是否存在可靠组合，而不是提前返回空结果。
6. 模型提示明确标注核心素材 ID，要求方案围绕核心素材展开，并引用至少一条其他素材。
7. 方案假设继续展示各条素材的贡献、最小版本和第一个验证动作。

## 空状态与错误处理

- 星库为空：选择器显示“素材星库还是空的”，生成按钮禁用，引导用户先保存素材。
- 只有一条可用素材：允许选中，但生成按钮禁用，提示“还需要至少一条可用素材”。
- 尚未选择核心素材：生成按钮禁用，提示“先选择一条核心素材”。
- 核心素材不存在、不属于当前用户或尚未分析完成：接口返回 404 或 400，前端刷新星库并提示重新选择。
- AI 没有找到可靠组合：沿用现有“暂未发现可靠方向”结果，不强行拼接。

## 接口与数据模型

- `IncubationRequest` 新增必填字段 `seed_material_id: UUID`。
- `query` 从前端输入改为由服务端根据核心素材标题与摘要生成的内部检索文本，并继续写入方案记录以兼容现有历史展示。
- `MaterialRetriever` 新增核心素材检索路径，返回顺序为核心素材在前、相关素材在后。
- 模型网关在生成提示中接收 `seed_material_id`，但不改变最终 `ProjectHypothesis` 响应结构。

## 响应式与无障碍

- 桌面端下拉列表与选择框同宽，生成按钮保持在表单右侧。
- 手机端表单仍为单列，下拉列表不超过视口高度并允许内部滚动。
- 选择器提供 `aria-expanded`、`aria-controls` 和 `role="listbox"`；选项使用 `role="option"` 与 `aria-selected`。
- 所有操作保留清晰的键盘焦点样式。

## 实现边界

- 保留可用时间和预算选项。
- 不增加多选、搜索、分页、拖拽排序或新的素材分类功能。
- 不修改素材编辑、重新分析、历史方案和反馈流程。

## 验收标准

1. 首页只出现一次“散落的念头、网页和问题存进来。”，并使用原一级标题视觉规格。
2. 项目生成区不再存在自由文本方向输入框。
3. 选择器能展示并单选当前素材星库中的可用素材。
4. 请求携带核心素材 ID，后端候选集始终包含该素材。
5. AI 方案至少引用核心素材和一条其他素材，或明确返回没有可靠方向。
6. 空星库、单条素材、无选择和失效素材均有明确状态。
7. 桌面与手机端无横向溢出，现有业务测试保持通过。
