# 第 1 阶段技术开发文档｜ShipCheck 后端 MVP

> 配套: PRD(ShipCheck 口述)、AI Agent 产品 Vibe Coding 通用技术栈手册 V2.1、技术适配声明。
> 本文档只覆盖第 1 阶段(后端 MVP)。不提前实现前端、用户账户、监控等。

## 一、阶段目标

- **交付范围**: 后端 MVP,打通两条主链路
  1. 验收模式: `POST PRD + URL` → 后台任务 → PRD 解析 → 生成 checklist → 逐条浏览器执行 + 采证 → 混元判定 pass/fail → 汇总报告(证据 + 修复任务)
  2. 审查模式: `POST PRD` → 后台任务 → 混元审查 PRD 逻辑 → 修改建议报告
- **阶段产物**: 可启动 FastAPI 服务;Swagger 文档;最小 static 验收页;mock pytest 套件;1 个 sample PRD
- **验收标准**: 两条主链路 mock 全跑通;真实混元冒烟(1 个真 PRD+1 个公开网址做验收、1 个真 PRD 做审查);Job 状态持久化可恢复;默认只读权限生效
- **明确不做**: 前端、用户账户、持续监控、视频证据、团队协作、CI 集成
- **主链路片段**: 用户提交 → Job 持久化 → 异步执行 → 状态机推进 → 报告持久化 → 用户轮询

## 二、技术适配摘要

- 引用《技术适配声明》;开发路径: 后端先行
- 采用默认: Python 3.11 + FastAPI + Pydantic + pytest + `/api/v1`
- 启用按需: SQLAlchemy + Alembic + SQLite;Playwright;本地文件存储;"提交+轮询"异步接口
- 偏离: AI 用混元(用户指定)
- 暂缓: 前端(第 2 阶段)、用户账户、监控、视频证据

## 六、数据/资产/状态

- 持久化: SQLite(SQLAlchemy + Alembic)
- 表:
  - `jobs`: id, type(acceptance|review), prd_text, target_url, status, created_at, started_at, finished_at, error_message, result_json
  - `checklist_items`: id, job_id, seq, description, expected, destructive, status, judge_result, judge_reason
  - `evidence`: id, item_id, kind(screenshot|dom|text|trace), path, content, created_at
  - `findings`: id, job_id, item_id(nullable), severity, category, message, suggestion
- 资产: 截图存 `./data/screenshots/`,元数据入 `evidence` 表;MVP 不自动清理
- 状态机:
  - Job: `pending → running → done | failed`
  - ChecklistItem: `pending → running → passed | failed | skipped`
  - 恢复: 重启时扫 `running` 的 Job 标记为 `failed`(interrupted);ChecklistItem 已 `passed` 的不重跑

## 七、API / 工具设计

- `POST /api/v1/acceptance` — req: `{prd_text, target_url, allow_destructive=false}`;resp: `{job_id, status:"pending"}`
- `POST /api/v1/review` — req: `{prd_text}`;resp: `{job_id, status:"pending"}`
- `GET /api/v1/jobs/{job_id}` — resp: Job + 关联 checklist_items + findings + 证据 URL
- `GET /api/v1/jobs` — 分页列表
- 统一错误: `{"error":{"code","message"}}`
- 异步: 提交即返回 job_id;后台 worker 推进状态;客户端轮询
- 浏览器工具白名单(动态 Agent):
  - `navigate(url)`, `click(selector)`, `type(selector, text)`, `screenshot()`, `get_text(selector)`, `get_dom(selector)`
  - 不提供 delete/post/submit 等破坏性动作;破坏性按钮只断言存在,不点击
  - 权限: `allow_destructive=false` 时所有写操作禁用
  - 预算: 每 checklist item 最多 15 步浏览器动作;超时 60s;最大步数 30

## 八、Prompt 设计

4 份独立 .md 文件,版本追踪:
- `prompts/prd_parse.md` — PRD → 结构化 features(JSON)
- `prompts/gen_checklist.md` — features → checklist items
- `prompts/judge.md` — checklist item + 证据 → pass/fail + reason
- `prompts/prd_review.md` — PRD → 逻辑漏洞/缺失/矛盾/模糊 + 修改建议
- 输出: 模型输出标准 JSON 格式;后端确定性解析 + Pydantic 强校验;格式不符有限重试 2 次,仍失败走统一错误

## 九、验收界面

- 功能: 选模式(验收/审查)→ 填 PRD(+URL)→ 提交 → 显示 job_id → 轮询状态 → 展示报告
- 原生 JS + fetch,不引入前端框架
